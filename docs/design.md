# Scrum Guild デザイン

状態: 草案。初版の全画面とダイアログ、クリアの演出をデザインシステムの部品だけで組んだ。まとめて確認してもらうところ

## 進め方

1. デザイン原則を決める（この文書）
2. 画面一覧と主なフローをまとめる（この文書）
3. スタイルタイルを3案作り、見た目の方向を選ぶ（`design/style-tiles.html`）
4. 要の1画面を本番の品質まで作り込む（`design/today.html`。トークンは `design/tokens.css`）
5. その画面から部品とトークンを取り出し、デザインシステムにする（`design/`。カタログは `design/index.html`）
6. 残りの画面は、デザインシステムの部品だけで組む。足りない部品は先にシステムへ足す

`mock/` の最初のモックは手順6で作り直す。

## デザイン原則

迷ったときは上の原則を優先する。

1. **記録は正確に、遊びは控えめに。** 数字、日付、状態、担当は一目で正しく読めること。ゲームらしさは記録の読みやすさを削らない範囲に置き、強く出すのは要所の1か所にとどめる。
2. **次にやることが最初に見える。** どの画面も、先頭に「今やること」か「今気にすること」を置き、詳細はその下に置く。要約が先、明細が後。
3. **状態は形と言葉で示す。** 期限切れ、重量オーバー、未記入、取り込み元で完了などは、色だけに頼らず、アイコンか文字でも示す。
4. **励ますが、競わせない。** 人を並べたり比べたりする表示を作らない。経験値の数値は本人に、レベルはみんなに見せる。演出は短く、1回で終わる。
5. **取り込んだものと自分たちのものを見分けられる。** 取り込み元の属性（タイトル、状態、期限）は Scrum Guild で編集できないと分かる見た目にし、出典（キーと取り込み元）を常に添える。
6. **言葉を切り替えても崩れない。** ゲームの言葉とスクラムの言葉は長さが違う。どちらでも折り返しや揃えが崩れないように組む。

## ロゴ

favicon と同じマーク（下の「favicon」）の横に、名前「Scrum Guild」を見出しの書体で組む。マークの形と色は全テーマで同じにし、タブの favicon と画面のロゴを同じ印に見せる。名前の書体だけがテーマで変わる。

- 置く所は、左のメニューの上（マーク 26px）と、枠の外の画面の先頭の紙（マーク 34px）。マークだけを置かない。名前は通常の文字の大きさなら1行に収まり、文字を拡大したときは、はみ出さずに折り返す
- マークは `aria-hidden` にし、名前は横の文字で読ませる。読み上げは「Scrum Guild」の1回になる
- マークの金と生成りはロゴだけの色で、操作、完了、印、経験値のどの色の役割にも入れない。favicon と同じ値を SVG に直に書き、tokens.css の変数にしない（テーマで変わらないことを値で保つ）
- 金の旗と背景の比は、白の紙で約3.46:1、シンプル（ライト）と中世風の左メニュー（`--color-sunken`）で約2.9〜3.0:1、ダークと現代風で4.7:1以上。マークは名前の文字と並べて置き、意味は文字で伝わるので、3:1 を割る面があっても色を変えない
- 本番は `src/lib/components/BrandMark.svelte`、見本は `design/kit.js` の `brandMark`。インラインの SVG にして、画像の読み込みを待たずに出す。`static/favicon.svg` と合わせた3つのファイルで、要素の並び（svg と2本の path だけ）、2本の path（旗とチェック）と viewBox、見本と本番の `class` と `aria-hidden` が一致することを `scripts/design-parity.test.ts` が確かめる。形や色を変えるときは3つをそろえて直し、`static/favicon.ico` は下の「favicon」の手順で作り直す

## favicon

金色の旗に生成りのチェックを置く。旗はチームで同じ目標へ進むこと、チェックはタスクの完了を表す。文字や旗竿、影、質感は付けず、全テーマで同じマークを使う。画面のロゴのマークも同じ形と色にする（上の「ロゴ」）。

原本は `static/favicon.svg`。金色は `#b58020`、チェックは `#fffaf0`、背景は透明。旗とチェックのコントラスト比は約3.32:1。下端の V 字の切れ込みと太いチェックが16pxでも残る形にする。`static/favicon.ico` は同じ SVG から作った16px・32pxの画像を含むフォールバックで、`src/app.html` から両方を参照する。形や色を変えたときは `pnpm exec node scripts/generate-favicon.ts` で ICO も作り直し、明暗背景で両サイズを確かめる。初回は `pnpm exec playwright install chromium` で描画用のブラウザを入れる。生成には既存の Playwright を使い、SVG と ICO を同じコミットに含める。

## Google のボタン

ログインの画面の Google のボタンは、Google のブランドの決まり（Sign in with Google）に合わせる。`.btn` の変種 `.btn.is-google` で、画面ごとの CSS は持たない。

- ロゴ: 公式の G の SVG（4色）を形も色も変えずに 20px で置く。本番は `GoogleMark.svelte`、見本は `design/kit.js` の `googleMark`。2つの path の並びと色を `scripts/design-parity.test.ts` が公式の値と突き合わせる
- 色: ライトは地 `#fff`、枠 `#747775`、文字 `#1f1f1f`。ダークは地 `#131314`、枠 `#8e918f`、文字 `#e3e3e3`。Google のブランドの固定色なので、トークンを通さず `components.css` に色を直に書く
- 明暗の切り替え: アプリのテーマに合わせる。`data-theme` が無い既定とシンプル（自動）だけ OS の明暗（`prefers-color-scheme`）に従う。シンプル（ダーク、`simple_dark`）と現代風（`modern`）はダーク版、シンプル（ライト、`simple_light`）と中世風（`medieval`）はライト版で、OS の明暗に依らない。ログインの画面は枠の外でテーマを既定に戻すので、実際には OS の明暗で決まる。テーマごとの分岐が効くのは、テーマを当てたまま出す見本とカタログ
- 書体と重み: アプリの本文の書体と、`.btn` の重みのまま（GitHub のボタンと同じ）。Roboto は足さない。角丸もアプリのもの（`--radius-1`）にする。書体と角丸は、公式から外す意図的な例外
- 並べ方: GitHub のボタンと同じ `.is-wide` で、同じ幅にする。ロゴと文字の間は 10px
- 文言: 辞書の `loginWithGoogle`（「Google でログイン」。ゲームとスクラムで同じ文）

### 運用

組織の外にあり、運用者だけが見る。組織の中のデータは出さない。

| 画面 | 主な中身 | 見る人 |
| --- | --- | --- |
| 運用 | 組織の一覧（slug、名前、ユーザー数と人数の上限、ワークスペース数、タスク数、添付ファイルの上限（合計は #68 で足す）、最後に使われた日時、停止の有無、管理者の状態）、組織の作成（slug、名前、最初の管理者）、停止と再開、管理者の指名し直し、人数と添付ファイルの上限の変更 | 運用者 |

- 一覧の列は、名前（状態の印。停止、管理者の状態）、人数 / 上限、<ワークスペース>の数、<タスク>の数、添付ファイルの上限、最後に使われた日時、操作。作った日時は列にせず、名前の列の2行目に「<slug> · 作成 <作った日時>」（`props-note`）と並べる。列を1つ減らし、1280px の画面で表が横スクロールせずに収まるようにするため。名前の列の印は、長い文でも列の幅で折り返す（`.table .is-name .chip`）。数の列は `is-num`（右寄せ、等幅の数字）。人数は「使っている人数 / 上限」で、人数が上限以上の組織には、その下に「上限に達した」（`chip is-warn`、`alert` のアイコン）を付ける。タスクの数は3桁ごとに区切る（`formatCount`）。添付ファイルの上限は、1 GB 以上は GB（1 GB = 1024³ バイト、小数1桁まで）、1 GB 未満は MB（「0 GB」と出さないため。`quotaSize`）で、使った量の合計は出さない（#68 で足す）。数と単位の間（「15 / 15」「30 GB」）は不可分の空白で、積んだ行でも割れない。最後に使われた日時と作った日時は、ブラウザのタイムゾーンで出す（`src/lib/format-datetime.ts`）。だれも使っていない組織は、最後に使われた日時の代わりに「まだ使われていない」（`props-note`）。数え方は `docs/data-model.md` の `users` の節の、運用者の組織の一覧の集計を書いた箇条書き。
- 組織の一覧の名前の横に、管理者の状態の印を付ける。管理者がいない組織は「管理者がいない」（`is-danger`）、指名した人がまだログインしていない組織は「管理者は指名済み、ログイン待ち」（`is-warn`）、Google の指名の招待の URL の期限が過ぎている組織は「管理者の招待の URL は期限切れ」（`is-danger`。運用者が指名し直す）。ログイン済みの管理者がいる組織には付けない。停止中の組織は「停止 <停止した日>」（`is-warn`）。解約で停止した組織には、続けて「<消す予定日> に消す」（`is-danger`）を付ける。日付はどちらも UTC の日付で出す（`formatUtcDate`）。消す予定日は停止した日の UTC の日付の30日後なので、ブラウザのタイムゾーンで出すと、日付がずれて30日後に見えない組織が出るため。`/operator` は運用者だけが開け、運用者でない人は `/` に戻す。
- 一覧の各行の右端（`is-actions`。`table-actions` で並べる）に、停止中でない組織は「停止する」（`btn is-sm is-quiet is-danger`）、停止中の組織は「停止の理由を変える」と「再開する」（どちらも `btn is-sm is-quiet`）を置く。右端のボタンは同じ要素のまま文字だけを替え、読み直しでフォーカスを失わない。読み上げの名前には「「<組織の名前>」を停止する」「「<組織の名前>」の停止の理由を変える」「「<組織の名前>」を再開する」と、どの組織かを添える。
- 一覧の表は `table.is-stacked`。760px 以下では列をやめ、1行を名前、集計と日時（どれも `data-label` で見出しを値の前に出す）、操作の順に縦に積む。固定した操作の列が名前の列を覆い、どの組織への操作か見えなくなるため。操作は折り返し、固定しない。ボタンは 44px 四方以上。
- 「停止の理由を変える」は、同じダイアログ（`OrganizationSuspendDialog`。見本は `design/kit.js` の `changeSuspension`）を、今の理由（消す予定日があれば解約）を選んだ状態で開く。`is-danger` は付けず、主ボタンは「変える」。今と同じ理由を選んでいる間は「変える」を `aria-disabled` にして押しても無視する（サーバーは 409）。停止した日時は変わらない。解約にすると、切り替えた日の UTC の日付の30日後が消す予定日になり、一時的な停止にすると消す予定日の印が消える。送っている間の扱いと失敗の扱いは停止のダイアログと同じ。
- 「停止する」は確認のダイアログ（`OrganizationSuspendDialog`。`Dialog` の `danger` で上の線を危険の色にする。見本は `design/kit.js` の `suspendOrganization`）を経て送る。停止の理由を「一時的に止める」（既定。消す予定は立てない）と「解約」（停止から30日後に運用の手順でデータを消す。それまでは再開できる）から選ぶ。主ボタンは `is-danger` の「停止する」、取り消しは「やめる」。送っている間の扱いは `WorkspaceCloseDialog` と同じ（「停止する」は `aria-disabled`、やめる・×・Esc・背景では閉じられず、「停止しています」は常に置いた `role="status"` の領域で伝える）。送り終えたら一覧を読み直してトーストを出す。失敗は3つ。通信や 5xx では、ダイアログを開いたまま、中の `role="alert"` に理由を出す。別の画面で先に停止されていた（409 の `conflict`）ときは、ダイアログを閉じ、「状態が変わっていました」とトーストで知らせて読み直す。見つからない、または操作できない（404、403）ときも、ダイアログを閉じ、理由をトーストで知らせて読み直す。
- 「再開する」は確認を挟まず送る。送っている間は、どの行のボタンも `aria-disabled` にして押しても無視する。送っている行のボタンの文字は「再開しています」にし（読み上げの名前は据え置く）、同じ文を常に置いた `role="status"` の領域でも伝える。結果の扱いは停止と同じ（トースト、読み直し）。停止と再開と理由の切り替えのトーストには、組織の名前を入れる（「「<組織の名前>」を停止しました」）。
- 停止のダイアログの本文は、組織の名前が長くても区切りが無くても折り返す（`.wrap-anywhere`）。「解約」の説明の日数は `PURGE_AFTER_DAYS` を辞書の `{days}` で埋める。
- 組織を作るダイアログでは、slug と表示名を入れ、最初の管理者のログインの手段（GitHub か Google）を選ぶ。GitHub はユーザー名を入れて「確かめる」を押すと、解決した人（アバター、ユーザー名、表示名、GitHub のユーザー ID）が出る。ユーザー名を表示名より目立たせる（表示名は自由に付けられ、似せたアカウントに見せかけられるため）。ユーザー名は1字違いでも別の人に当たるので、運用者が確かめるまで「作る」は押せない。ユーザー名を直すと確かめた結果は消え、もう一度確かめるまで作れない。GitHub の組織のアカウントは、個人のアカウントでないことを示して断る。GitHub に届かないときは、入力の誤りと分けて、時間をおいてもう一度試すよう伝える。Google を選んだときの欄はメールアドレスで、Google にはメールアドレスから本人を引く口が無いので、確かめる手順は置かず、入れた時点で作れる。形の合わないメールアドレス（ASCII の外の文字を含む、`@` が1つでない）は、欄の下に理由を出す。
- 作っている間は、入力欄と手段を読み取り専用にし、「作る」は `aria-disabled` にして押しても無視する。閉じる操作（×、Esc、背景、やめる）も無視する（応答を見失わないため）。slug は入力欄で切らず、貼り付けた値が長すぎれば作る前の確かめで断る。
- 作れたか分からない失敗（通信の切れ、5xx、slug の重なり）の後は、一覧を読み直し、同じ slug の組織があればダイアログの中で示す。名前も入力と同じなら、そこから組織の URL の表示へ移せる。この表示では、組織の URL と、一覧の管理者の状態（いない、ログイン待ち、期限切れ、ログイン済み）だけを出す。既にあった組織の管理者が、ダイアログで確かめた人だとは限らない（別の運用者が、別の人を指名して作ったかもしれない）ので、ログインするユーザー名は出さない。名前が違うときは、この入力で作ったものではないかもしれないと出す。失敗は、欄に紐づくものは失敗した欄へ、紐づかないものは失敗の枠へフォーカスを移す。
- ダイアログの中に、読み上げの領域（`role="status"`）を1つだけ常に置き、文字だけを替える（確かめています、確かめました、作っています、作りました）。完了の表示では、フォーカスを本文に置く。
- 作った後は、同じダイアログを完了の表示に切り替える。組織の URL（`<画面のオリジン>/<slug>/`）とコピーのボタン、「GitHub の `<ユーザー名>` でログインするよう伝えてください」を出す。Scrum Guild はメールを送らず、運用者が伝える。閉じると一覧を読み直した結果が見える。
- Google で指名して作った後の完了の表示は、組織の URL の代わりに招待の URL（`<PUBLIC_ORIGIN>/invite#<秘密>`）とコピーのボタン、「次のメールアドレスの Google アカウントでログインするよう伝えてください」とメールアドレス（等幅で、狭い幅では折り返す）を出す。招待の URL は応答の本文にだけあり、この表示を閉じると二度と出せないこと、期限（作ってから14日。期限の日時も添える）、期限までに本人へ伝えることを、注意の枠（`is-warn`）で添える。表示を閉じると、招待の URL を持つ状態を捨てる。

### 経路と組織の枠

- 経路: 組織の画面は `/<slug>/...`、ワークスペースの画面は `/<slug>/w/<ワークスペースの ID>/...`（例 `/aoba/w/019a.../backlog`。ID をそのまま使う）。組織の外は `/`（ログインの直後の振り分けと組織の選択）、`/login`、`/operator`、`/invite`。経路の最上段に使う名前は slug にできない。
- ログインの直後の `/`（`src/routes/+page.ts`）: `my-organizations` の結果で振り分ける。届いた招待が無く、入れる組織が1つならその組織へ。入れる組織が無い運用者は `/operator` へ。それ以外（入れる組織が2つ以上、届いた招待がある）は、`/` がそのまま組織の選択の画面になる。入れる組織も届いた招待も無く、運用者でもない人は、ログインできず、セッションも持てない（ログインのときに断り、持っていたセッションは `my-organizations` の呼び出しで消えて 401 になり、ログインの画面へ戻る）。そのため、組織の選択の画面に、入れる組織も届いた招待も無い空の状態は出ない。出るとすれば、組織を失った直後のわずかな間だけ。
- 組織の選択: 「入れる組織」は管理者か所属のある組織だけ。「届いた招待」は、承諾待ちの招待があるすべての組織（入れる組織の分も含む）を、組織の名前だけで1組織1件に出す。行は、その組織の招待の画面（`/<slug>/invitations`）へのリンク（`a.choice`）。入れる組織が無く、招待だけが届いている人には、届いた招待から組織を選んで承諾すると入れることを書く。長い名前と slug は折り返す。
- 招待の画面（`/<slug>/invitations`、`src/routes/[slug]/invitations/` と部品 `InvitationInbox.svelte`。見本は `design/login.html` の「届いた招待」）: その組織に自分宛てに届いた承諾待ちの招待（`invitation-list`）を並べる、枠（左のメニューと上の帯）の無い画面（`Gate`、`GateSheet`）。行は `.choice.is-static` で、ワークスペースの名前を太字に、その下に「組織の名前・招待した人さんから・ロール・招待した日」を出し、中の `.form-actions` に「承諾する」（`is-primary`）と「辞退する」（`is-quiet`）を置く。ボタンの読み上げの名前は「<ワークスペースの名前>への招待を承諾する」。閉じたワークスペースへの招待は、「承諾する」を押せなくし（`disabled`）、終了しているため承諾できず、辞退はできることを行の中に書く。招待が無ければ空の状態を出す。紙の下に、組織に入れる人には組織の画面へ戻るリンク、だれにも組織の選択へ戻るリンクとログアウトを置く。
  - 出し分け: 組織に入れる人は、`/<slug>/invitations` を開いたときだけ、組織の枠の代わりにこの画面を出す（組織の枠の `+layout.svelte` が、`page.data` の `invitationPage` を見て枠を出さずにページを出す）。組織に入れず（`organization` の操作が 404 の `not_found`）、組織の選択（`my-organizations`）の届いた招待にその slug がある人（承諾待ちの招待だけの人）には、`/<slug>` の下のどの経路（`/<slug>` 直下を含む）でも、組織の枠の load が読んだ `invitation-list` でこの画面を出す（読めなかったときは読み込みの失敗）。招待だけの人は `organization` の操作を読めないので、`invitation-list` が返す組織の言葉づかいと既定のテーマを当てる（`applyInvitedOrganization`）。組織に入れる人には、組織の枠が当てた値のまま（`Gate` の `keepsOrganization` で既定に戻さない）。
  - 結果はトースト（root のレイアウトに置くので、画面が移った後も4秒残る）で知らせる。承諾すると「招待を承諾しました」を出し、そのワークスペースの画面（`/<slug>/w/<ID>`）へ、すべての load を読み直して移る。辞退すると「招待を辞退しました」を出す。招待が残らなければ、招待だけの人は組織の選択（`/`）へ、組織に入れる人は `/<slug>` へ、読み直して移る。招待だけの人が最後の招待を辞退すると、入れる組織も招待も無くなり、組織の選択の読み取りでセッションが消えて、理由の無いログインの画面へ戻る。辞退したことは、移った後も残るトーストで伝える（ログインの画面に理由を足さない）。招待が残れば一覧を読み直し、消えた行の位置の行（無ければ前の行）の押せる最初のボタンへ、行が無ければ紙の下の戻るリンクへフォーカスを移す。送っている間は、どの行のボタンも `aria-disabled` にして押しても無視し、押したボタンの文言と読み上げの名前を「招待を承諾しています」「招待を辞退しています」にそろえる（同じ文を常に置いた `role="status"` の領域でも伝える）。
  - 失敗は、紙の中の `callout is-warn`（`role="alert"`）に理由を出し、一覧を読み直す。見つからない（404。取り消された、別のアカウントに宛てた招待）、状態が変わっていた（409 の `conflict`）、終了した（409 の `workspace_closed`）、もう所属している（409 の `already_member`）、通信できない、そのほかで文を分ける。招待だけの人は、読み直すと招待が残らないこと（一覧が空か 404）を先に確かめ、残らなければ、組織の枠が「見つからない」になって理由が消えるので、理由をトーストで出して組織の選択（`/`）へ移す。401 はログインの画面へ移す。
  - 紙の下の戻るリンクは「<組織>の画面へ戻る」（組織に入れる人だけ。区切りの無い長い組織名で狭い幅からはみ出さないよう、組織の名前は入れない）と「<組織>の一覧へ」。招待だけの人に当てる組織のテーマは `data-theme` の属性だけで、`localStorage` には覚えない（まだ入っていない組織の値を、次の読み込みの先当てに持ち越さない）。
- 枠の外の画面（組織の選択、見つからない、読み込みの失敗、運用）では、テーマと言葉づかいを既定（属性なし、ゲームの言葉）に戻し、`localStorage` の値も消す。どの組織の値も持ち越さない。外から組織の枠へ移る間は、300ms たっても終わらないときだけ、読み込み中の表示（`LoadingSheet`。見出しと題名を持つ）を出す。読み上げの領域は root のレイアウトに常に置き、文字だけを替える。
- `/<slug>` のレイアウト（`src/routes/[slug]/+layout.ts` と `+layout.svelte`）: `organization` の操作の結果（組織の名前、言葉づかい、既定のテーマ、この組織での自分、所属するワークスペース）で `data-theme` と言葉づかいを当て、枠（左のメニューと上の帯）を出す。枠は root のレイアウトではなくここに置き、ログインと組織の選択の画面には出さない。上の帯には、この組織での自分の名前（アカウントのメニューのボタン。下の「アカウントのメニュー」）と、管理者なら管理者の印を出す。
- 組織に入れない slug と存在しない slug は、どちらも同じ「見つからない」の画面（枠なし）で、API はどちらも 404。見つからないのは、API が `not_found` の 404 を返したときだけ。ほかの失敗（通信の失敗、5xx、403、`not_found` 以外の 404）は、見つからない画面ではなく「読み込めませんでした」（題名も同じ）と「もう一度試す」を出す。「もう一度試す」は、読み直している間は `aria-disabled` にして押しても無視し（フォーカスを残す）、状態は常に置いた `role="status"` の領域に文字で出し、また失敗したら「まだ読み込めませんでした」を出す。
- 停止した組織の画面: 停止した組織を開いたとき、停止していなければ入れた人には、API が 403 の `organization_suspended` を返す。`/<slug>` のレイアウトはこれを受けたら、枠なしの「この組織は停止しています。運用者に問い合わせてください。」の画面（`Gate`、`GateSheet`、`EmptyState`。見つからない画面と同じ作りで、題名と文が違う。組織の選択へ戻るリンクを置く）を出す。入れない人には、今までどおり「見つからない」の画面を出す。停止した組織にしか入れない人は、ログインできる条件を失ってセッションが消えるので、組織の枠の読み込みで 401 を受けて `/login?error=suspended` へ移り、ログインの画面に「所属しているか招待されている組織は停止しています。運用者に問い合わせてください。」を出す（組織の中の操作が 403 を返す前に、ほかに入れる組織が無ければセッションを消して同じ 401 にする）。
- 組織の切り替え: ブランドの下に置く開閉するメニュー。入れる組織が2つ以上あるか、届いた招待があるときだけ出し、中は各組織へのリンクと、最後に組織の選択の画面（`/`）へ戻るリンク。狭い幅でも出す。
  - 届いた招待があるときは、ボタンに「届いた招待あり」の印を出し、一覧へ戻る行に「招待が届いています」を添える（招待が見える入口は組織の選択の画面だけなので、1組織でも出す）。
  - 閉じるのは、ボタン、メニューの外を押す、Tab で外へ出る、リンクを押す、Esc。メニューの中にフォーカスがあるときに閉じたら、ボタンにフォーカスを戻す（Tab で外へ出たときは、出た先にフォーカスを置く）。Esc は変換中は無視し、閉じたときはほかの Esc の処理へ伝えない。
  - 組織が多いときは、一覧が画面の高さの 40% までで、中でスクロールする。760px 以下と、指で押す画面では、リンクの高さを 44px 以上にする。
  - 別の組織や組織の選択の画面へ移っている間は、ボタンの文言を「移っています」に替え、読み上げの領域（常に置く）に伝える。
- アカウントのメニュー（組織の中）: 上の帯の自分の名前と管理者の印を、押すと開くボタンにする（`AccountMenu.svelte`）。名前と管理者の印の後ろに、自分のレベルの小さい紋章（`Emblem` の `small`。`organization` の操作の `me.level`）を添える（見本の `accountMenuHtml` と同じ並び。ボタンの読み上げの名前は変えない）。中は「ログアウト」の1項目（後で「自分の設定」も入る。今は左のメニューから開く）。ボタンの読み上げは「<名前>。アカウントのメニュー」で、管理者の印があるときは名前の後ろに「（<管理者>）」を含める。リストは帯の下に重ね（帯の高さを変えない）、広い幅ではボタンの右端に合わせて開く。760px 以下は帯が左に寄ってボタンが左端に来るので、ボタンではなく帯を基準に、左右の余白（セーフエリアを含む）の内側へ広げる。どちらの幅でも画面の外へはみ出さない。760px 以下と、指で押す画面では、ボタンと項目の高さを 44px 以上にする。
  - 開閉は組織の切り替えと同じ: ボタン、メニューの外を押す、Tab で外へ出る、Esc。メニューの中にフォーカスがあるときに閉じたら、ボタンにフォーカスを戻す。ログアウトの項目を押しても閉じない。
  - 確認のダイアログは挟まない。失うのは再ログインの手間だけで、メニューを開く1手が誤操作を防ぐ。左のメニューの下や、帯に並べたボタンは、狭い幅で名前と離れる、誤って押しやすい、帯が混むので採らない。
- ログアウト: 組織の外（`/`、`/operator`）は、紙（`GateSheet`）の一番下に `btn is-sm is-quiet` の「ログアウト」を置く（`LogoutButton.svelte`。`/` では「運用の画面へ」と同じ並び）。`Gate` に帯を足さない。読み込みの失敗（`LoadFailed`）と見つからない画面には置かない（`/` へ戻ればログアウトできる）。
  - 押すとボタン（メニューの項目も）を止めて、文言を「ログアウトしています」にする（`aria-disabled`。二重に送らない）。「ログアウトしています」は、常に置く `role="status"` の領域（メニューとボタンのそれぞれの隣）にも入れて読み上げに伝える。呼び出しは `src/lib/logout-action.svelte.ts` の 1 か所で、メニューの項目とボタンが共有する。
  - 結果の振り分けは `src/lib/logout.ts`。成功と、401 の `unauthenticated`（もうセッションが無い）は、`location.replace('/login?logged_out=1')` でページごと読み直す。`goto` は使わない（組織のテーマ、言葉づかい、読み込み済みのデータがメモリに残るため）。`assign` でなく `replace` にして、履歴に残さない（「戻る」で前の人の組織の画面が戻らないようにする。共有の端末の対策）。それでも bfcache から画面が戻る場合に備え、root のレイアウト（`src/routes/+layout.svelte`）が `pageshow` の `persisted` で `location.reload()` する。ログアウトに限らず、bfcache から戻ったすべての画面を読み直すので、外のページから「戻る」で帰ったときも、開いていたダイアログと保存していない入力は消える。ほかのタブでログアウトした後や、セッションが切れた後に戻った画面でも、前の人のデータを出さないことを優先する。`return_to` は付けない。
  - 通信の失敗、5xx、そのほかは、トースト「ログアウトできませんでした。時間をおいてもう一度試してください。」を出して今の画面に留まり、ボタンを戻す。`/login` へ移すと、Cookie と行が残ったまま「ログアウトできた」ように見える（共有の端末で危ない）。
  - `/login?logged_out=1` は、見出しの下に `callout is-info` の「ログアウトしました。」を出す。`?error=` があるときは、エラーだけを出す。
  - サーバーの `logout` は今のセッションだけを消し、同じ人のほかの端末のセッションは残す。
- 未ログイン（401 の `unauthenticated`）は `/login?return_to=<今のパスとクエリを encodeURIComponent したもの>` へ移す。ログインの後に戻す処理はログインの画面が受け持つ。入れたはずの組織が停止しているだけで入れる組織を失った人の 401 は、`details.reason` が `suspended` になる。画面（`src/lib/login-redirect.ts` の `loginUrl`）は、渡された応答のどれかがこの理由を持つとき、`&error=suspended` を足す。組織の枠は、組織の操作とアカウントの組織の選択を同時に呼ぶので、セッションが消える前に読まれた側の理由の無い 401 があっても、もう片方の理由で足す。
- `users.last_seen_at` は、`organization` の操作を呼んだときに、前回から1時間以上たっているときだけ書く。この書き込みは応答を待たせず、失敗しても画面の値は返す（ログには例外の名前だけを残す）。
- 自分の今日が空のときの管理者向けの案内は、組織にワークスペースが1つも無いときは最初のワークスペースを作る案内（ワークスペースを作るダイアログを開くボタンを置く）、ワークスペースはあるが自分の所属が0件のときは所属が無いことの案内（ボタンは置かない）。メニューには、所属するワークスペースが無い人に、組織の画面（自分の今日、通知、自分の設定、組織の管理）だけを出す。「組織の管理」は管理者にだけ出す。

  - ストーリーのダイアログ（`StoryDialog`）は、作るときも直すときも同じ欄（タイトル、<受け入れ基準>、本文、<期日>、リンク）を出す。見出しの右上の「<ストーリー>を作る」と、木の行の題から開く。タイトル以外は空でよい。<受け入れ基準>と本文は、この版では文字のまま持つ（1万字まで。改行とタブ以外の制御文字は断る。前後の空行と末尾の空白を落とし、先頭の行の字下げは残す）。リンクは http と https の URL だけ（2048 字まで。ユーザー名とパスワードを含む URL は断り、保存する値は解釈した URL にそろえる）。リンクに使える値が入っていれば、入力欄の横に「開く」（`rel="noopener noreferrer"` で新しいタブ。読み上げの名前に新しいタブで開くことを含める）を置く。欄の並びは `.form-row.is-start`（欄の下のエラーで隣の欄がずれない）。区分の選択欄はエピックのダイアログと同じで、エピックの下のストーリーには出さず、エピックの区分を「親から引き継ぎ」を添えて文字で出す（区分は親のないストーリーだけが持つ。開いた後にエピックの下へ移されていて断られたとき（409 の `has_parent`）は理由を出し、閉じたときに読み直す）。
    - 直すときは、開いたら `story-get` で1件を読む（<受け入れ基準>と本文は長いので、木には載せない）。読んでいる間は読み込み中を出して欄を出さず、読めたらタイトルへフォーカスを移す。読めなければ（404 以外）理由と「もう一度試す」を出す。404 は、トーストで知らせて閉じ、木を読み直して、見出しへフォーカスを移す。
    - 開いたときの値と比べて変えた欄だけを送り、変えた欄が無ければ何も送らずに閉じる（別の人が別の欄を直していれば両方が残り、同じ欄は後の保存が勝つ）。日付の入力が途中までしか打たれていなければ（`validity.badInput`）、期日の欄にエラーを出して送らない。サーバーが 400 で断ったときは、どの欄かが分からないので、タイトルを責めず、全体の文で知らせる。
    - 終了したワークスペースでは読み取り専用で開き（欄は `readonly`。日付の入力は `readonly` を受けないので、読み取り専用の text に日付を出す）、保存のボタンを出さず、案内の `callout.is-info` を出す。送っている間の扱いと、古い応答を捨てる `generation` は起票のダイアログと同じ。保存できたら閉じて、木を読み直す。文言はストーリー用の辞書の項目を使う（タスクのダイアログの項目を流用しない）。
  - 期日の印（`DueChip`）は、過ぎた期日が `.chip.is-danger`（警告のアイコンと「<期日>切れ」と日付）、今日が `.chip.is-warn`（時計のアイコンと「今日まで」）、今週が `.chip.is-warn`（時計のアイコンと「今週」と日付）、それ以外が `.chip`（時計のアイコンと日付）。今週は、週の始まりからの7日間。完了にした行と完了したストーリーは色を付けない。読めない日付は、落とさずに色なしの印で元の文字を出す。判定は `src/shared/due.ts` の純粋な関数で、今日の日付（ワークスペースのタイムゾーン）と週の始まりは `backlog-tree` の応答の `today` と `week_start` を使う（ブラウザの時計とタイムゾーンに頼らない）。ストーリーの行とタスクの行に出す。
  - 完了にした行は、読み直すまで完了の印（テーマごとの違いの表）を付けてその場に残す。折りたたみの件数は読み直した値で、その行は読み直すまで入らない。起票したタスクは読み直さずに、親の配下（親なしなら一覧の末尾）へ足し、親の「全体」のポイントにも足す。ストーリーの下のタスクも同じ操作で完了にできる。完了の操作を送っている間は、丸を薄くして（`.done-btn[aria-disabled]`）押しても無視し、常に置いた読み上げの領域に「<完了>にしています」を出す。別の画面で先に完了にされていたとき（409 の `conflict`）は、同じ完了の印で示す。タスクが無い（404）か、ワークスペースが閉じた（409 の `workspace_closed`）ときは、一覧を読み直す。
  - 起票のダイアログ（`TaskCreateDialog`）は、見出しの右上の「<起票>」か、ストーリーの行の「＋<タスク>」から開く。親の選択欄は、親なしと、完了していないストーリー（エピックの下のものも含め、木の順）。エピックの下のストーリーがあるときだけ、候補を親のエピックごと（見出しはエピックの題。同じ題の別のエピックは分ける）の `optgroup` にまとめ、親のないストーリーは「親なしの<ストーリー>」にまとめる（同じ題のストーリーが、別のエピックの下にありうるため。`src/lib/parent-options.ts`）。親を移すダイアログの候補も同じ。候補に無い親の ID で開いたときは、親なしで開く。終了したワークスペースでは、起票と完了の操作を出さない。起票の送信で `workspace_closed` を受けたら、理由を出し、ダイアログを閉じたときに読み直す。親が消えている（404）か完了している（409 の `conflict`）ときは、理由を出し、その場で木を読み直して候補を更新する。選んでいた親が候補から消えていたら、親なしに戻して親の選択欄へフォーカスを移す（ダイアログは閉じない）。担当の選択欄は親の横（`.form-row.is-start`。片方の下にだけ知らせが出ても、もう片方が下へずれない）に置き、既定は担当なし。候補は開くたびに `member-list` の `members`（そのワークスペースに今所属している人）を読み直し（前に開いたときの候補と知らせは消す）、読めなければ担当なしだけで作れ、読めなかったことと「もう一度試す」（`.btn.is-sm.is-quiet`。読めたら担当の選択欄へフォーカスを移す）を添える。親が無事なのに 404 を受けたら、選んだ担当が所属を外れたので、理由を出し、候補を読み直して担当なしに戻し、担当の選択欄へフォーカスを移す。作れたら、親の行が畳まれていれば開き、トーストに親の題を添える。リポジトリは見本の `repoPicker` と同じく、1回押して選ぶボタンの並び（`RepositoryPicker`。`.segmented`、`role="radiogroup"`。先頭が「なし」）で、既定は「なし」、一覧が1つだけならそれを選んでおく。下に「複数のリポジトリにまたがる作業は、リポジトリごとに<タスク>を分けます。」を添える。一覧を読めなかったときはその代わりに「<区分>とリポジトリの一覧を読み込めませんでした。」を、リポジトリが0件のときは「リポジトリは<リーダー>が設定の画面で足せます。」を添える。消えたかどうかは、一覧を読み直せたときだけ決める（読めなかった一覧は空なので、どれも消えたように見えるため）。区分の選択欄は親なしのときだけ出し、親を選んでいるあいだは、その親の区分（無ければ<区分>なし）を「親から引き継ぎ」を添えて文字で出す。選んだリポジトリか区分が送るまでに削除されていた（404）ときは、一覧を読み直して「なし」に戻し、理由を出して、その欄へフォーカスを移す。
  - 木の行には区分とリポジトリの名前を `.chip.is-name`（`DefinitionChip`。名前は 50 字まで付けられるので、行の幅を超えたら折り返す。区分はタグ、リポジトリは git のアイコンで、状態の印と見分ける）で出す（`backlog-tree` が引き継ぎを解いた区分とリポジトリを返す）。区分は振った行（エピック、親のないストーリーとタスク）にだけ出し、配下の行では繰り返さない（エピックとストーリーは題の横、タスクはタイトルの下の `.entry-meta`）。リポジトリはタスクの行のタイトルの下に、見本の `repoTag` と同じく git のアイコンを添えて出す。どちらも、種類を見えない文字（「<区分>：」「リポジトリ：」）で読み上げに添える。画面で行を動かした後、読み直すまでの間は、印を動かす前の値のまま出す。
  - 空の状態は3つ（エピックかストーリーが1件でもあれば、どれも出さない）。書き込めて、タスクも完了済みも無いときは「まだ<タスク>がありません」と起票の案内。終了していて、どちらも無いときは「終了した<ワークスペース>には、<タスク>を作れません」。未完了が0件で完了済みがあるときは、折りたたみの行の上に「未完了の<タスク>はありません」と次の一歩（書き込めるときは起票の案内、終了していればその理由）を出す。
  - 並べ替えと親の移動（`task-move`、`story-move`）。書き込めるときだけ、木の上に、優先順と、行の「上へ」「下へ」、Alt と ↑ ↓ の案内（`.action-note`。辞書の `backlogOrderNote`）を出し、続けてつまみのドラッグの案内（`.drag-note`。辞書の `backlogDragNote`）を添える（エピックの並べ替えは #308 で足す）。`.drag-note` は、つまみを出さない狭い幅と指で押す画面では隠す。
    - タスクの行（`.entry-end`）とストーリーの行（`.tree-end`）の右に、`.order-actions` の `icon-btn` で「上へ」「下へ」を置く。読み上げの名前は「上へ: <題>」「下へ: <題>」。動かすのは同じ親の中の1つ（親のないストーリーと親のないタスクは、それぞれの段の中。エピックの下のストーリーは、そのエピックの中）。端で動かせない向きは、押した後もフォーカスが残るよう `disabled` でなく `aria-disabled` にする。行の中（リンクとボタン）にフォーカスがあるときの Alt と ↑ ↓ も同じで、ブラウザの既定の動きは止める。完了にした行（読み直すまでその場に残る行）には出さないが、その行の前後へは動かせる（下へは次の行の直後、上へは2つ上の行の直後、先頭になるなら直前の行なし）。
    - タスクの行には「親を移す」（`swap` のアイコン。読み上げの名前は「親を移す: <題>」）も置く。押すと小さなダイアログ（`MoveParentDialog`。見出しは「「<題>」の親を移す」）で、移す先を親なしと、完了していないストーリー（エピックの下のものも含む。今の親を除く）から選ぶ。移す先の末尾に置き、畳まれていれば開く（親のストーリーがエピックの下なら、エピックの行も開く）。親のないタスクは、移す先のストーリーが無ければ出さない。行は移す先の下に作り直されるので、新しい行の「親を移す」へフォーカスを移す。
    - ストーリーの行にも「親を移す」を置く。同じダイアログで、移す先を親なしと、完了も中止もしていないエピック（今の親を除く）から選び、移す先の末尾に置く（`story-move` に直前の行を送らない）。親のないストーリーは、移す先のエピックが無ければ出さない。親が完了か中止していて断られたとき（409 の `parent_completed`）は「<完了>か中止した<エピック>の下へは移せません。一覧を読み直します」。読み上げは「「<題>」を<エピック>「<親の題>」の末尾へ移しました」。
    - どちらも先に画面を動かしてから送り、送る順は押した順に守る。動かした並びと親の「全体」のポイント（移してきた行の分を足し、外へ移した行の分を引く）は、読み直すまで画面に持つ。失敗したら理由をトーストで知らせて木を読み直す（並びは読み直した値に戻る。読み直しが失敗しても、画面で動かした並びは捨てる）。404 は「一覧が変わったため移せませんでした。一覧を読み直します」（消えたのが動かした行か、直前の行か、親かは分からない）、`workspace_closed` は「終了した<ワークスペース>には書き込めません」。409 の `conflict` は `details.reason` で分け、`parent_completed` は「<完了>した<ストーリー>の下へは移せません。一覧を読み直します」、`task_completed` は「この<タスク>は<完了>しています。一覧を読み直します」、`changed` は「ほかの画面で変わったため、移せませんでした。一覧を読み直します」。それ以外（`ties`、通信の失敗、5xx）は「移せませんでした。一覧を読み直します」。401 は読み直してログインの画面へ移す。読み直した後は、フォーカスのあった行の同じ操作（`data-row-id` の行の中で何番目のリンクかボタンか）へ戻し、その行が無ければ見出し（`h1.page-title`）へ移す。
    - 送り終える前に木が読み直されたとき（ストーリーを保存した、別の移動が失敗したなど）は、まだ送っていなかった移動を捨て、送っている移動が終わった後にもう一度読み直す（送っている移動が、読み直しの後に届くことがあるため）。捨てた移動があれば「動かしている間に一覧が読み直されたため、一覧を読み直しました。並びが変わっていなければ、もう一度動かしてください」をトーストで知らせる。
    - 端の行で Alt と ↑ ↓ を押したときは、読み上げの領域に「いちばん上です」「いちばん下です」を出す。
    - 動かした結果は、常に置いた見えない `role="status"` の領域で読み上げる（「「<題>」を N 番目に移しました」「「<題>」を<ストーリー>「<親の題>」の末尾へ移しました」、親のストーリーがエピックの下なら「「<題>」を<エピック>「<エピックの題>」の<ストーリー>「<親の題>」の末尾へ移しました」、「「<題>」を親なしの末尾へ移しました」）。並べ替えで行の要素が動いてフォーカスが外れたら、同じ要素へ戻す。
    - ドラッグ（`BacklogDnd`、`src/lib/backlog-dnd.svelte.ts`。何を落とせるかの判定は部品に依らない純粋な関数 `src/lib/backlog-drop.ts`）。書き込めるときだけ、タスクの行（`TaskEntry`）とストーリーの行（`TreeStory`）の先頭に、つまみ（`.grip`。`grip` のアイコン）の列を置く（行に `.has-grip`）。つまみは飾り（`aria-hidden`）で、つかむ場所はここだけ。題の文字は選べ、ボタンを押すつもりで動き出さない。キーボードと読み上げの人は「上へ」「下へ」と Alt と ↑ ↓ を使う。つかめない行（完了にした直後の行、エピックの行）は、列だけ空ける（`.grip.is-off`）。エピックの行そのものの並べ替えは #308 で足す。書き込めないとき、狭い幅（760px 以下）、指で押す画面（`pointer: coarse`）では、つまみを出さず、列も空けない。
      - 落とせる場所は、サーバーが受ける行き先に合わせる。タスクの親は完了していないストーリーか親なし、ストーリーの親は完了も中止もしていないエピックか親なしで、タスクをエピックの直下へ、ストーリーをストーリーの下へは落とせない。サーバーが断るのは親が変わるときだけなので、今の親の中の並べ替えは、親が完了か中止していても落とせる（ボタンと同じ）。画面で<完了>にしたタスクは、つかんでも落とせない（その行の前後には落とせる）。落とせない場所と、元と同じ位置には、線も囲みも出さず、離しても送らない。
      - 行き先の行の上半分に重ねると前、下半分に重ねると後ろの、行と行の間の線を出す（`[data-drop="before"]`、`[data-drop="after"]`。`--color-accent` の 2px と左端の小さな丸）。線は行き先の階層の字下げ（`--row-indent`）から始める。開いた<ストーリー>の最後の<タスク>の下の線は<タスク>の字下げ、次の<ストーリー>の前の線は<ストーリー>の字下げから始まるので、見分けられる。<ストーリー>の行の前後の線は、開いた配下の途中に入らないよう、配下を含めた塊（`.tree-group`）の上端と下端に引く。
      - 親の行（<タスク>を運ぶときの<ストーリー>の行、<ストーリー>を運ぶときの<エピック>の行）に重ねると、行を囲む（`[data-drop="into"]`。`.dropzone.is-over` と同じ `--color-accent` の枠と `--color-accent-soft` の地）。この行は行全体を囲みの落とし先にする（<タスク>は<ストーリー>の間に置けず、前後の線の落とし先が無いため）。離すと、その配下の末尾に入り（`after_task_id`、`after_story_id` を省く）、畳まれていれば開く。
      - 「<完了> N 件を折りたたんでいます」の行と空の案内の行（`.tree-folded`）の前後は、その配下の末尾として扱う（親なしの折りたたみの行は、親なしの末尾）。完了にした直後の行はつかめないが、その前後には落とせる。
      - 親なしの段が空のときは、その種類の行をつかんでいる間だけ、段の場所に落とし先の行を1つ出す（`.tree-slot` の中の `.dropzone`。ラベルは「親なしの<タスク>へ移す」「親なしの<ストーリー>へ移す」）。<タスク>をつかんでいる間は、親なしのタスクも<完了>の折りたたみの行も無いとき、<ストーリー>をつかんでいる間は、親のないストーリーが0件のときに出す。重ねると囲み（`.is-over`）になり、離すと親なしの末尾に入る（`after_*_id` を省く）。つかんでいないときは出さない。
      - 落としたら、ボタンと同じ移動を同じ待ち行列（`MoveQueue`）に積む。先に画面を動かし、押した順に送り、失敗したら上と同じ文で知らせて読み直す。行き先の直前の行を `after_*_id` に渡し、先頭なら null、末尾に置くときは省く。ドラッグの間に木が読み直されたら、そのドラッグは取りやめ、離しても送らない。落とせる場所で離したときは、送る前に捨てた移動と同じ文（`moveReloaded`）をトーストで知らせる。
      - 結果は上と同じ `role="status"` の文で読み上げる。親が変わったときは、移した先の親を含む文にする。末尾に入ったときは「…の末尾へ移しました」、途中に入ったときは「「<題>」を<ストーリー>「<親の題>」の N 番目に移しました」（親のストーリーがエピックの下なら「「<題>」を<エピック>「<エピックの題>」の<ストーリー>「<親の題>」の N 番目に移しました」、ストーリーの親を変えたときは「「<題>」を<エピック>「<親の題>」の N 番目に移しました」、親なしなら「「<題>」を親なしの N 番目に移しました」）。同じ親の中では「「<題>」を N 番目に移しました」。フォーカスは動かさない（マウスの操作）。
      - つかんだ行は元の位置で薄くする（`.is-dragging`）。落とした行は、背景を `--color-accent-soft` から地の色へ約 0.8 秒（`--duration-flash`）で戻し、`--color-accent` の 1px の枠も同じ長さで消して光らせ（`.is-dropped`。地と `--color-accent-soft` の差が小さいテーマでも見えるように。同じ行を続けて落としても、もう一度光る）、畳んだ先や遠くへ落としても行き先が分かるようにする。`prefers-reduced-motion` のときは光らせず、薄くするのも切り替えだけにする。一覧の端に寄せたときの自動スクロールは機能なので、止めない（auto-scroll のパッケージ。画面全体を動かす）。色は既存のトークンだけで、4つのテーマに新しい色は足さない。

  - 完成の定義の節は、見出しが「<完成の定義>」、説明が「すべての<タスク>に共通する完了の基準。<バックログ>の上と、完了の操作の横に出します。」（スプリントの画面の完了の列に出すようになったら、説明にも足す）。中身は「Markdown」の欄（`.textarea`、8 行）と、「Markdown で書けます。空にして保存すると、どこにも出しません。」の添え書きと「保存する」（`.btn.is-primary`）。区分とリポジトリと違い、書いた文を「保存する」でまとめて送る（`workspace-dod-update`）。保存した値から変えていないと「保存する」は `aria-disabled` で、押すと「保存した内容から変わっていません」を出す。整え方（改行をそろえ、前後の空行と末尾の空白を落とす）は本文と同じで、空白だけなら空にする。10 万字を超える（「<完成の定義>は 100,000 字までです」）か見えない文字を含むときは、送らずに欄の下に理由を出してフォーカスを欄へ戻す。送っている間は欄を読み取り専用にし、読み上げの領域に「<完成の定義>を保存しています」を出す。通ったら、トースト（「<完成の定義>を保存しました」、空にしたら「<完成の定義>を空にしました」）を出して枠を読み直す（`invalidate('app:workspace')`。バックログの画面と詳細の引き出しは、枠の値を出す）。欄の文は、保存した値から変えていない間だけ、読み直した値に合わせる（書いている途中の文は上書きしない）。断られたときは、閉じていれば「終了した<ワークスペース>には書き込めません」をトーストで知らせて枠を読み直し、403 と 404 は「保存できませんでした。操作できない状態です。画面を読み直しました。」を欄の下に出して枠を読み直し、409 の `conflict`（同時に書かれた）は「ほかの画面で同時に変わったため、保存できませんでした。もう一度「保存する」を押してください。」を出す（書いた文は欄に残す）。通信の失敗と 5xx と、画面の検査を通った後の 400 は「<完成の定義>を保存できませんでした。もう一度「保存する」を押してください。」。429（回数の上限）も同じ文。書きかけ（保存した値から変えた文。送っている間も数える）があるまま別の画面へ移る（左のメニュー、戻る／進む）ときは、タスクの詳細の引き出しと同じく、アプリの中の確認のダイアログ（`ConfirmDialog`）が「書き続ける」（主ボタン）か「捨てる」かを選ばせる。捨てると決めたら移り、戻る／進むは履歴をその分だけ動かす。同じ画面のままの移動（`?task=` で引き出しを開くなど）は確かめない。ページを離れる操作（タブを閉じる、外のサイト）は、ブラウザの確認に任せる。終了したワークスペースでは、欄を出さずに Markdown の部品で読み取り専用に出す（空なら「まだ<完成の定義>がありません。」）。
  - 見本の「保存する」でまとめる形は採らず、行ごとにすぐ書く。一覧は `.order-list` で、先頭にドラッグのつまみ（`.grip`）の列を持ち、行の中身（`.order-main`）に名前（`InlineEdit`。名前そのものが押せるボタンで、押すと入力欄になり Enter で確定）と、区分だけ「月ごとに計上する」の切り替え（`.toggle`。読み上げの名前は「月ごとに計上する: <名前>」）を並べ、右に「上へ」「下へ」「削除」（`.order-actions`。読み上げの名前は「上へ: <名前>」など。端の向きは `aria-disabled`）を置く。足すのは一覧の下の欄（`.input-row` に入力欄と「<区分>を足す」「リポジトリを足す」）で、末尾に足す。同じ名前（409 の `duplicate_name`）と数の上限（409 の `limit`、50 件）は、欄の下に理由を出してフォーカスを戻す。名前の変更で同じ名前を断られたときも、入力欄の下に理由を出す。
  - 削除は確かめのダイアログ（`ConfirmDialog`。見出しは「「<名前>」を削除する」）を挟む。区分では「振っていた<エピック>、<ストーリー>、<タスク>は<区分>なしに戻ります。完了の記録は元の<区分>のまま残ります。」、リポジトリでは「振っていた<タスク>はリポジトリなしに戻ります。」と出す。消したら、同じ位置の行（無ければ前の行）の削除ボタンへ、一覧が空なら足す欄へフォーカスを移す。
  - 足す、切り替え、並べ替え、削除は1本ずつ送り、送っている間はほかの操作を押しても無視する（ボタンと切り替えは `aria-disabled`。押せない見た目にする）。名前の確定は `InlineEdit` が二重に送らないので、ほかの操作と重なっても送る。送っている間は「<区分>を保存しています」「<区分>を削除しています」を読み上げる。書いた後は画面の値だけを読み直す（`app:workspace-settings`）。読み直しが失敗したときは、画面全体を読み込みの失敗に替えず、前に読めた一覧を残したまま、節の先頭に「一覧を更新できませんでした」と「もう一度試す」（`.callout.is-warn` の操作付き。組織の管理の画面と同じ）を出す。並べ替えた後は、同じ行の同じボタンへフォーカスを戻し、「「<名前>」を N 番目に移しました」を読み上げる（同じ文が続いても読まれるよう、いったん空にしてから入れる）。ほかの画面で消されていた（404）、変わっていた（409 の `changed`）、閉じた（`workspace_closed`。枠ごと読み直す）ときは、トーストで知らせて読み直す。足す操作の 404 はワークスペースが見つからないので、「足せませんでした。画面を読み直します」を出して枠ごと読み直す。
  - 0件のときは「まだ<区分>がありません」と下の欄から足せることを出す。終了したワークスペースでは、名前（と区分の「月ごとに計上する」の印）だけを読み取り専用で出し、足す欄と操作を出さない。
  - 行は、先頭のつまみ（`.grip`。飾りで `aria-hidden`）のドラッグでも並べ替えられる（`ListDnd`、`src/lib/list-dnd.svelte.ts`。行き先の判定は `src/lib/list-drop.ts`）。つかむ場所はここだけで、名前の文字は選べる。キーボードと読み上げの人は「上へ」「下へ」を使う。行の上半分に重ねると前、下半分に重ねると後ろの、行と行の間の線（`[data-drop="before"]`、`[data-drop="after"]`。バックログの木と同じ見た目）を出し、元と同じ位置には出さず、送らない。落としたら、「上へ」「下へ」と同じ送り方（`category-move`、`repository-move`）で、行き先の直前の行（先頭なら直前の行なし）を渡す。読み直した後に、動いた行を光らせ（`.is-dropped`）、「「<名前>」を N 番目に移しました」を読み上げる。フォーカスは動かさない。つかんだ行は元の位置で薄くする（`.is-dragging`）。
  - 終了したワークスペースでは、つまみを描かず、列も空けない（バックログの木と同じ）。送っている間（`busy`）は、つまみを出したまま、つかめなくする（全行のつまみが点滅しないように）。狭い幅と指で押す画面では、つまみを出さず、列も空けない（並べ替えは「上へ」「下へ」で行う）。
  - 取り込み元の入る先との結び付け（見本のリポジトリの行の選択欄）は #67 で足す。

- スプリントの作成（開始日、長さ、名前）、開始（ゴールの入力）、終了（持ち越し先、ゴールの達成）のダイアログ
- エピックやストーリーの削除（配下を残すか、まとめて削除するか）のダイアログ
- エピックの中止のダイアログ
- ストーリーの作成と変更のダイアログ（バックログの木の行から開く。終了したワークスペースでは読み取り専用。見本はカタログの「ダイアログと演出」）
- エピックの作成と変更のダイアログ（バックログの見出しと木のエピックの行から開く。欄はタイトル、本文、期日、リンク。終了したワークスペースでは読み取り専用。見本はカタログの「ダイアログと演出」）

## 決めた方向

見た目はテーマで切り替える（要件定義の「ゲームの仕組み」）。テーマは「シンプル（自動、ライト、ダーク）」「中世風」「現代風」。部品と画面の構成はどのテーマでも同じで、変わるのは `design/tokens.css` の変数と、決まった少しの飾りだけにする。

最初は案 A（ギルドの帳簿）を土台に、レベルと積載量だけ案 B（冒険者の装備画面）の表現を使う方向で決めた。それが今の中世風になった。会社に入れても違和感のない見た目が要るので、シンプルを足して既定にした。『俺だけレベルアップな件』のステータス画面に寄せた見た目として、現代風を足した。

### どのテーマにも共通すること

- **色の役割:** 操作と選択の色、完了の色（完了の印とクリアだけ）、印の色（依頼主の印と通知の数だけ）、経験値の色（経験値とレベルとレイドだけ）を分け、他の意味を持たせない。状態の色は必ずアイコンか文字と一緒に使う。
- **文字:** 本文は BIZ UDPGothic、キーと日付とポイントは IBM Plex Mono。見出しとレベルや経験値の数字の書体は、テーマで変わる。
- **レベル:** 六角の紋章に Lv の数字。経験値のゲージは10の目盛りで刻み、見込みは斜線で示す。
- **積載量:** 5% 刻みの目盛りのゲージに作業量を重ね、許容幅の両端を縦の線で示す。判定（重量オーバー、範囲内、余力あり、未見積もりあり）は色に加えてアイコンと文字で出す。
- **演出:** 完了の印とクリアの演出は短く1回で終わり、prefers-reduced-motion のときは止める。

### テーマごとの違い

| | シンプル | 中世風 | 現代風 |
| --- | --- | --- | --- |
| 見立て | 業務の道具 | 冒険者ギルドの帳簿 | ハンターに届くシステムのウィンドウ |
| 明暗 | 自動、ライト、ダーク | ライトだけ | ダークだけ |
| 色 | 白か暗い灰の地に青の操作色。完了は緑 | 紙の地に墨の文字、藍の操作色。完了は朱 | 濃紺の地に光る青の操作色。経験値は紫、完了は緑 |
| 見出しの書体 | ゴシック | 明朝（Zen Old Mincho） | Chakra Petch とゴシック |
| 数字の書体 | ゴシック | Chakra Petch | Chakra Petch |
| 角と線 | 角を少し丸める（6px）。区切りは細い線 | 角を立てる（2px）。台帳の左と見出しの下は二重罫 | 角を立てる（2px）。区切りは細い線 |
| 影 | 薄い影 | 貼り出した紙の影 | レベル、積載量、貼り紙、ダイアログの枠が光る |
| 完了の印 | 緑の丸にチェック | 朱の判子「完」 | 光る緑の丸にチェック |
| クリアの演出 | 緑の丸に「クリア」 | 朱の二重丸の判子「クリア」 | 光る枠のウィンドウ「クリア」が開く |

現代風で光らせるのは、ゲームの要所（レベル、積載量、貼り紙、ダイアログ、クリアの演出）だけにする。台帳や表など記録を読む所は光らせない。作品のロゴ、書体、枠の形は写さず、雰囲気だけを取り込む。

### 飾りの決まり

- テーマの違いは、まず tokens.css の変数（色、書体、太さ、角、区切りの線、影、面の地）で表す。
- 変数で表せない飾りは、components.css の末尾の「テーマの飾り」にまとめる。飾りは、完了の印、依頼主の印、クリアの演出、現代風の光だけにし、増やすときはこの文書に書き足す。ロゴはテーマで変えない（「ロゴ」）。
- 中世風と他とで文字が変わる飾り（「依 頼 書」とエピックの言葉）は、`.orn-medieval` と `.orn-plain` の両方を書き、テーマで片方を隠す。
- `data-theme` の値は DB の列挙（`simple`、`simple_light`、`simple_dark`、`medieval`、`modern`）と同じにする。属性がなければシンプル（自動）として扱う。
- 部品を足したら、カタログのテーマの切り替えで4つの見た目（シンプルのライトとダーク、中世風、現代風）を確かめる。

- 本番の Svelte では、tokens.css と components.css をそのまま読み込み、kit.js の関数を1つずつコンポーネントにする（次の節）。
- tokens.css と components.css は `src/routes/+layout.svelte` が `design/` から import する。複製しない。見本の Worker（`wrangler.design.jsonc`）の build watch paths が `design/*` なので、この2つを直すと見本も出し直される。

### Markdown の本文

タスクの本文、コメント、決まった欄、ストーリーとエピックの本文を `Markdown.svelte` で描く。見た目は components.css の `.doc-box` の中の要素（見出し、段落、リスト、チェックリスト、引用、コード、区切り線、打ち消し線、表）として持ち、トークンだけを使う。見本はカタログの「Markdown の本文」。

- 構文木を `src/lib/markdown.ts` が安全な節（段落、見出し、引用、リスト、コード、区切り線、表と、文字、コード、強調、打ち消し線、リンク、改行）に直し、`MarkdownBlocks.svelte` はその節を再帰で描くだけにする。HTML の文字列を作らない（`{@html}` を使わない）。インラインの `style` 属性も使わない（CSP）
- 生の HTML（`html` の節）は、書かれたままを文字で出す。`.doc-literal`（`white-space: pre-wrap`）で、改行を保つ
- リンクは絶対の `http:` と `https:` だけ。URL を `new URL` で解析して判定し、解析した形を `href` にする。相対リンク、`mailto:`、`javascript:`、`data:`、2048字（`MAX_URL_LENGTH`）を超える URL、ユーザー情報の付いた URL（`https://名前@ホスト/`。行き先を偽れる）は文字で出す。参照形式（`[x][1]`）は定義を引いて同じ規則にかけ、自動リンクにも同じ規則が効く。中身が空のリンク（`[](https://…)`）は URL を文字にする。リンクは `rel="noopener noreferrer"` と `target="_blank"` で、新しいタブで開くことは、全リンクが `aria-describedby` で指す隠した文（辞書の `markdownNewTab`。`hidden` の `span` を枠に1つ置く）で伝える。リンクの文字に混ぜないので、リンクの名前にも、チェックリストの箱の名前（`aria-labelledby`）にも入らない。組織の中のリンク（タスクの ID の参照）は、その機能を作るときに決める
- 画像は読み込まない。`http:`、`https:` の画像は代わりの文字（無ければ URL）を文字にしたリンクにし、それ以外は代わりの文字だけにする。リンクの中の画像は、`<a>` を入れ子にしないよう文字だけにする。Scrum Guild の添付ファイルだけを画像として出す口は、添付ファイルの機能で足す
- 入れ子（引用、リスト、表、強調、リンク）は32段まで描き、超えた分は書かれたままの Markdown を文字（`.doc-literal`）で出す。本文は最大10万字で、`>` を並べるだけで再帰の部品のスタックがあふれるため
- 出力の総量の上限: 文字（本文、`href`、切り出した原文の長さの合計）は40万字（`MAX_OUTPUT_CHARS`。本文の最大の4倍）、節は5万（`MAX_OUTPUT_NODES`）。節の上限は描画の時間で決めた。手元（Chromium、Mac）で、節を DOM にする時間は節の数にほぼ比例し、見出し、段落、リスト、表、リンクが混ざった93k字（節が約2.2万）は約255ms、チェックリスト中心の96k字（節が約3.7万）は約1.07秒、節が20万に近い表は約1.7秒止まった（CPU を4倍に絞ると約4倍）。正当な最大の本文（節が約3.7万）が通る5万にしてある。短い行を詰めて並べた本文は、10万字に届く前に上限を超える（例: `- a` の項目を2.5万行、3列の表を1.2万行、1文字の段落を3.3万個）。表のセルとリストの項目を1つの節と数えるため。超えた本文は `parseMarkdown` が変換をやめて `null` を返し、文字のまま出す。備える相手は、長い URL の定義1つに短い参照を並べて、参照ごとの `href` の複製で出力を膨らませる本文。URL の長さの上限と、この総量の上限の両方で抑える
- 表の本文の行は、見出しの列数に切り詰め、足りない分は空のセルで埋める。`th` は `scope="col"` 付きで出す
- 横にスクロールするコード（`pre`）と表の枠（`.doc-table`）は、`tabindex="0"`、`role="region"`、辞書の名前（`markdownCodeRegion`、`markdownTableRegion`）を持つ。Safari はスクロールする枠に自動でフォーカスを置かないので、キーボードだけでは右の列やコードの末尾へ届かないため
- 密なリスト（項目の間にも、項目の中の段落の間にも空行が無い。リストと全項目の mdast の `spread` が偽）は、項目の段落を `<p>` で包まない。項目の中に空行で区切った段落があるリストは、段落が連結しないよう `<p>` で包む
- 自動リンクの mdast の拡張が持つ `transforms` は、構文木を再帰で歩き、6000段ほどの引用でスタックがあふれるので外す。リンクは micromark 側の字句が作るので、結果は変わらない。違いは、閉じていない `[` の後ろの URL（`[ https://example.com`）が、リンクにならないこと
- 変換は Web Worker（`src/lib/markdown.worker.ts`）で行い、メインのスレッドで走らせない。`*_` の連なりや深い入れ子の本文は、変換に数秒から分かかり、同じ組織のメンバーが書いた本文で画面が固まるため。Worker は全部の本文で1つを共有し、要求を1本ずつ送る（`src/lib/markdown-parser.ts`）
  - Worker は、束の評価を終えると `ready` を返す。変換の時間切れ（1秒。`MARKDOWN_TIMEOUT_MS`）は、`ready` を受けて要求を送った時点から数える。起動（束の取得と評価）には別の上限（10秒。`MARKDOWN_START_TIMEOUT_MS`）を持ち、超えるか、起動の前に Worker がエラーを返したら、以後は Worker を使わず、待っていた要求も含めて全部を文字のまま出す。再読み込みするまで整形せずに出し続ける（立て直さない）。待ちが何件あっても、再帰せずに順に片付ける
  - 変換が時間切れになった本文は、Worker を `terminate()` して次の要求のために作り直し、文字のまま出す。待たされた時間は数えない
  - 変換の失敗（`null`、Worker のエラー、`messageerror`）と Worker が使えない環境も、本文を文字のまま出す。Worker の中で失敗したときは、本文を含めず、失敗の種類だけを `console.error` に出す
  - 結果は本文をキーに100件、量（本文の字数と節の数の合計）で200万まで覚え、どちらかを超えたら古いものから捨てる（LRU。`src/lib/markdown-session.ts`）。件数だけだと、上限近い本文が並んで数百 MB に届くため。時間切れと失敗の本文も覚え、二度と Worker に送らない。同じ本文の変換が進んでいれば、結果を分け合う。Worker に送る前に取り下げた要求の `null` は、時間切れではないので覚えない。送り済みの要求は、待つ人が全員いなくなっても進めて結果を覚え、同じ本文の新しい要求は、その変換に相乗りする。覚えは本文だけで決まる値で、組織を切り替えても残る（他の組織の本文を読む経路は無いので、混ざらない）
  - `source` が変わったら古い要求の結果を捨て、新しい結果が来るまで前の描画を残す（文字に戻さない）。部品が消えたら待ちの要求を取り下げる。待つ間は枠に `aria-busy="true"`。この振る舞いは `MarkdownSession`（parser を差し込める）に持ち、`Markdown.svelte` の配線は `bindMarkdownView`（`src/lib/markdown-view.svelte.ts`）に出して、部品はそれを呼ぶだけにする。結果は `$state.raw` で持つ。前の描画を残すので、別の対象の本文に1つの部品を使い回す画面（タスクの切り替えなど）は、`{#key}` で対象ごとに作り直す
  - 段階の描画（`src/lib/markdown-render.ts`）: 変換済みの節は、先頭から、1フレームの時間の予算（30ms。`MARKDOWN_FRAME_BUDGET_MS`）ごとに増やして描く。フレームは `requestAnimationFrame` で予約する。節の重み（節、リストの項目、表のセルの数の目安）が1500以下の短い本文は、区切らず1回で全部描く（ちらつかせない）
    - 区切る単位は、トップレベルの節。項目の多い1つのリストと、行の多い1つの表は、項目と行で区切る（チェックリストと大きな表を、1フレームで描かないため）。引用の中のリストなど、入れ子の中は区切れない。入れ子の深い1つの節が大きいと、その1つは1フレームで描くので、節の総量を `MAX_OUTPUT_NODES`（5万）で抑える
    - 描き終わるまで、枠に `aria-busy="true"`。`source` が変わったら描きかけを捨て、描いてある分を残して次の結果を待つ。部品が消えたら、予約したフレームを取り消す
    - 1回に描く量は、直前の実測（`flushSync` までの時間）から予算に収まるよう決める。ただし、描き済みの重みの5%を下限にする。スタイルとレイアウトは script の時間に入らず、描き済みの量に比例して毎フレーム掛かるので、実測だけで決めると1回の量が縮み、描き終わらない
    - 配列は100個ずつの頁に分け（`MARKDOWN_PAGE_SIZE`）、外側の `{#each}` が頁を、内側が頁の中を描く。描き済みの頁は同じ配列なので、Svelte は照らし合わせずに済む。項目の中で、作り直される節（`node`）を読まない（`{@const}` で1回だけ取り出す）。読むと、段階の描画のたびに描き済みの全項目が描き直される
    - 測った値（本番の build を Chromium で開き、Long Tasks API で測る。Mac。CPU を絞った4倍は括弧の中）: 最長の停止は、混ざった93k字（節が約2.2万）で139ms（586ms）、チェックリスト 1.6万項目（節が約4.8万）で284ms（792ms）、表 8200行（節が約4.9万）で134ms（573ms）、段落 2.4万で103ms（477ms）。段階にしない（1つの節ごとに1回で描く）と、同じ本文の最長の停止は、混ざった本文で約255ms（4倍で約1.0秒）、チェックリスト 1.6万項目で約0.94秒、表 8200行で約0.39秒。描き終わるまでは、順に0.8秒、2.6秒、1.1秒、1.2秒（4倍で3.3秒、16秒、10秒、6.6秒）。最長の停止が100msを超えるのは、描き済みの量に比例するレイアウトが、後ろのフレームほど長いため
  - 時間切れと失敗で文字のまま出すときは、枠の上に `.props-note` で「整形せずに表示しています」を出す（辞書の `markdownPlainNote`）。変換を待つ間は出さない。本文は `.doc-box.is-plain`（`white-space: pre-wrap`）に入れる
  - Worker は自分のオリジンのファイル（`/_app/immutable/workers/`）で、CSP は `worker-src` を足さず `script-src 'self'` で通る。`blob:` と `data:` の Worker にしない
  - Worker の束が読む `decode-named-character-reference` は、DOM を使わない版にそろえる。既定の `browser` の版は `document` を呼ぶので、Worker では `document is not defined` で落ちる。`vite.config.ts` の `resolve.alias` で dev と build の両方に効かせ、場所は `scripts/markdown-worker-entities.ts`（直の依存）
  - 安全の規則（リンク、画像、HTML、入れ子、出力の上限）は、変換の単体テストと、変換済みの節を描く `MarkdownBlocks` の描画テストで守る
- 見出しは `headingStart` の段から始め（`#` が `h3`、`##` が `h4`）、`h6` で止める（`headingStart` は、数でなければ既定の3、範囲外は1と6に丸めた値）。大きさは要素でなく Markdown の段のクラス（`.doc-h1` から `.doc-h6`）で決める。`.doc-h1` は `--text-lg`、`.doc-h2` は `--text-md`（引き出しの題 `.drawer-title` の `--text-xl` より小さい）。`.doc-h3` から下は本文と同じ大きさで、罫（`.doc-h3`）と字間（`.doc-h5`、`.doc-h6`）で見分ける。先頭でない見出しに `margin-top` を足す
- チェックリストの箱は `disabled` で出す（押しても保存されない）。`li.is-task`。箱は項目の中身と `aria-labelledby` で結ぶ（id は `$props.id()` に節の位置を足し、本文が並んでも衝突しない）。項目の印を消す一覧には `role="list"` を付ける。順序付きのリストは番号を残す（箱は浮かせて中身を回り込ませる）
- GFM は自動リンク、打ち消し線（`~~` のみ）、表、チェックリストの4つ。脚注は本文ごとに `id` を生やし、同じ画面に本文が並ぶと衝突するので入れない
- 表の列の寄せは `th` と `td` の `.is-center`、`.is-right`。表は `.doc-table` で包み、幅が足りないと横に動かす。セルは `overflow-wrap: break-word`（枠の `anywhere` を引き継ぐと、列が1文字幅までつぶれる）。枠（`.doc-box`）は `overflow-x: auto` で、深い入れ子が狭い幅からはみ出さないようにする

### タスクの詳細の引き出し

見本は `design/kit.js` の `drawerHtml` とカタログの「引き出し」（ふだんの形、直している途中、完了したタスク、リンクを断られた、終了したワークスペース、取り込んだタスク、読み込み中、読み込めなかった）。捨てるかを確かめるダイアログと削除の確認の見本は、カタログの「ダイアログと演出」。

- 開閉は URL の `?task=<ID>` で決める。行のタイトルのリンクで開き、閉じるときは、開いている画面（バックログ、メンバーなど）の URL から `task` だけを外す（ほかのクエリは残し、履歴は積まず置き換える。バックログへ移さない）。戻る／進むでも開閉でき、存在しない ID（別の組織の ID を含む）と ID の形でない値は、トーストで知らせて閉じ、木を読み直す。ワークスペースのどの画面の上にも、レイアウトが置く
- 広げた形（`drawerState.full`）は画面の状態として持ち、開き直しても、次に開くタスクでも残す（ページを読み直すと戻る）。横に出した形は `aria-modal="true"` で、幕を出し、外側（左のメニュー、上の帯、画面）を `inert` にする（幕、ダイアログ、トーストは残す）。広げた形は `aria-modal="false"` で、幕と `inert` を外し、左のメニューを押せる。メニューが上の帯になる 760px 以下では広げると全幅になる。引き出しがもともと全幅になる 620px 以下では、広げるボタンを出さず、広げた形を無視して横に出した形（モーダル）として扱う。`inert` は引き出しを開いた時点の兄弟の要素に付けるので、開いた後に足された要素（開いてから出るダイアログの外の要素など）は対象にならない
- 閉じる操作は、閉じるボタン、幕、Esc。確認のダイアログが開いている間の Esc はダイアログだけを閉じる。日本語の変換中の Esc（`isComposing`、`keyCode` 229）は閉じる操作にしない。閉じたら（戻る／進むで閉じたときも）、開いた行のタイトルのリンク（`data-task-id`）へフォーカスを戻す。行が無いとき（削除した、見つからない、画面にまだ無い）は、画面の見出し（h1）へ移す
- 開いたらフォーカスを閉じるボタンに置き、読み込めたら見出し（h2、`tabindex="-1"`）へ移す（開いた直後の読み上げは、引き出しの名前と見出し）。名前（`aria-labelledby`）は、見出しの中のタイトルの文字だけを指す（押して直す案内の文字は含めない）
- 読み込み中は見出しにタスクの言葉を置き、枠に `aria-busy`、読み上げの領域に「読み込んでいます」を出す。読めなければ失敗の文と「もう一度試す」を出し、フォーカスを「もう一度試す」へ置く。引き出しが読み直すのは、保存の後の木（`invalidate('app:backlog-tree')`）と、閉じたと分かったときと未ログインのときのワークスペースの枠（`invalidate('app:workspace')`）だけで、組織の枠の load は走らせない（`invalidateAll` を使わない）ので、組織の枠の読み込みの失敗で引き出しと書きかけが消えない。ワークスペースの枠の読み直しが通信か 5xx で一時的に失敗したときは、直前に読めた同じワークスペースの値を保つ（`settleWorkspace`。見つからない、入れない、未ログインは保たず、覚えた値も消す）。組織の枠が引き出しの外の理由（画面の移動、枠を開き直す操作）で読み直されて失敗したときは、これまでどおり「読み込めませんでした」を出す
- 欄ごとにその場で直し、保存した欄は、応答でその欄だけを入れ替え、画面を読み直して木の行に反映する。タイトルとリンクは、値そのもの（`.edit-trigger`）を押すと入力欄に替わり、Enter か「保存」で確定、Esc か「取り消し」で戻す。本文は「編集」で書く欄に替わり、保存か取り消しで描いた本文に戻る（Enter は改行。Esc は引き出しの閉じる操作）。確定か取り消しの後は、押したボタンへフォーカスを戻す。リンクの「開く」は、直している間は隠す。保存に失敗したら、欄のすぐ下に理由を出す
- ポイントと期日は選んだら保存する。ポイントの保存は1本ずつ送り、送っている間に選び直した分は最後の選択だけを溜めて、送り終えた後に送る（矢印キーで動かしても要求が飛び交わず、応答の順が前後しない）。先の要求が失敗しても、送っている間に選び直した最後の選択は送る（タスクが消えたときと、完了にされていたときは、同じ要求を繰り返さず捨てる）。保存した値と同じ選択は送らない。期日は、年が4桁そろった値（1000 年以降）だけを、600ms 待ってから（カレンダーで選んだとき）か、欄を離れる／Enter で保存する。送っている間に次の値を選んだら、入力欄を先の応答で上書きせず（入力が最後に送った値と同じときだけ保存した値に合わせる）、送り終えた後に次の値を送る。失敗したときも、打っている次の値は消さない。「クリア」を押した後は、フォーカスを期日の入力欄へ移す。1行の入力欄（タイトル、リンク）と期日の Enter は、日本語の変換中（`isComposing`、`keyCode` 229）は送らない。打ちかけの年（0002、0020 など）は送らず、欄を離れたときに直っていなければ知らせ、期日の横に「クリア」を添える
- 保存を断られたときの文は、送った欄で分ける。ポイントは「完了した<タスク>の<ポイント>は直せません」、取り込んだタスクのタイトルとリンクはその旨、ほかの競合（同じ欄を同時に直した）は「ほかの人が同時に直したため、保存できませんでした。最新の内容を読み直したので、もう一度試してください。」。どれも今の値を読み直し、その値（完了しているか、取り込んだタスクか）で文を決める。引き出しが閉じた後に返った保存と削除の応答も黙って捨てず、通ったら木を読み直してトーストで知らせ、失敗はトーストで知らせる
- 本文は Markdown の部品で描く。見出しは h3 から始める（`headingStart` の既定。引き出しの題が h2）。相対リンクと `mailto:` は文字で出る。空は「まだ書かれていません。」
- 本文の下に完了の帯（`.done-bar`）を置く。完了していなくて書き込めるときは「<完了にする>」（`.btn.is-primary`）で、押したら確かめのダイアログを挟まずに `task-complete` を送る（送っている間は `aria-disabled` にし、読み上げの領域に「<完了>にしています」）。通ったら、トースト「<タスク>を<完了>にしました」を出し、完了の印（`.hanko`）と「<完了> <日時>」（ブラウザのタイムゾーン）に替え、履歴と木を読み直して、押したボタンは消えるので印へフォーカスを移す。409 の `conflict`（別の画面で先に完了にされた）は「この<タスク>は、すでに<完了>です」と知らせて読み直し、`workspace_closed` は「終了した<ワークスペース>には書き込めません」と知らせて枠を読み直し、404 は消えたタスクとして閉じる。通信の失敗と 5xx は「<完了>にできませんでした」。完了したタスクには、印と完了の日時を出す（終了したワークスペースでも出す）。完了を戻す操作は #240 で足す。帯は上端でそろえ（`align-items: flex-start`。完了の印と日時は `.done-bar-done` にまとめて縦の中心をそろえる）、右（`.done-bar-dod`）には、題「<完成の定義>」（`.done-bar-dod-title`。引き出しの題 h2 の次の h3）の下にワークスペースの完成の定義を Markdown の部品で描く（本文の見出しは h4 から。`.done-bar-dod` の中の `.doc-box` は枠と余白を外し、見出しも帯の小さい文字のまま罫を付けない）。本文（`.done-bar-dod-body`）は高さを 12em までに抑えて中で送り、長い定義でも帯が伸びない。送る領域はキーボードで届くよう `tabindex="0"` と `role="region"` にし、名前は題（`aria-labelledby`）。空なら出さず、終了したワークスペースの完了していないタスクでは、完成の定義があるときだけ帯を出す
- 完了したタスクのポイントは、欄を読み取り専用にする（API も 409）。薄めず（`.segmented.is-readonly`）選んだ値の色を保ち、鍵のアイコンと「完了した<タスク>の<ポイント>は直せません」を添えて、理由の文を欄（`radiogroup`）の `aria-describedby` に結ぶ。ほかの属性は完了の後も直せる
- 取り込んだタスクは、タイトルを直せず（押せない。「取り込んだ<タスク>のタイトルは、ここでは直せません」を添える）、リンクの欄を出さず、削除でなくアーカイブで外す（削除の代わりに「取り込んだ<タスク>は削除せず、<アーカイブ>へ移して外します。」を添える）。取り込み元のキーと期限の表示と、取り込み元の期限を編集できないと分かる見た目は、取り込みの機能の Issue の仕事（見本には残してあり、今は取り込んだタスクの期日も編集できる）
- 書きかけは、タイトル、リンク、本文の直している途中で、保存と同じ整え方（タイトルは前後の空白を除く、リンクは解釈した URL、本文は改行と前後の空行の整理）の後も、値が保存した値と違うもの。保存の要求を送っている間も数える（確認を出す。送っている要求は止められずそのまま通り、通れば木を読み直して知らせる。送っている間に閉じられて失敗すると入力が消えるので、閉じる要求を待たせず、確認で止める）。まだ送っていない期日の入力（600ms の待ちの間、打ちかけ、送っている間に選んだ次の値）も書きかけの扱い。コメントは、新しいコメントの欄に文字があるとき（整えた後に空でない）と、直している途中で直す前の本文と違うとき（どちらも送っている間も数え、消されて保存できなくなった書きかけも数える）が書きかけ。書きかけがあるまま閉じる（×、幕、Esc）か、別のタスクや別の画面へ移る（戻る／進む、左のメニュー）と、アプリの中の確認のダイアログ（`ConfirmDialog`。ブラウザの `confirm` は使わない）が「書き続ける」（主ボタン、開いたときのフォーカス）か「捨てる」かを選ばせる。捨てると決めた後、戻る／進むは履歴をその分だけ動かす（`history.go`）。ページを離れる操作（タブを閉じる、外のサイト）は、ブラウザの確認に任せる
- 削除は「この<タスク>を削除する」（`.btn.is-quiet.is-danger`）で、手で作ったタスクを、作った人とリーダー（管理者を含む）にだけ出す。それ以外の一般のメンバーには、ボタンの代わりに「削除できるのは作った人と<リーダー>です。」だけを添える。確認のダイアログ（「やめる」が主ボタン、上辺を赤。長いタイトルは折り返す）を挟み、消したら引き出しを閉じ、トーストで知らせ、木を読み直して、フォーカスを見出しへ移す。経験値の付いたタスクも論理削除なので、経験値は残る
- 期日の欄には、値があるとき、入力欄（と「クリア」）の横に期限の印（`DueChip`。バックログの行と同じ部品で、過ぎた、今日、今週、それ以外を、色とアイコンと文字で示す。完了したタスクは色なし）を出し、保存した値で出し直す。印を決める今日と週の始まりは `task-detail` が返す（ワークスペースのタイムゾーン。ブラウザの時計に頼らない）。終了したワークスペースの読み取り専用の表示にも同じ印を出す
- 終了したワークスペースでは、読み取り専用で開く。直す口（押せるタイトル、リンク、「編集」、ポイントと期日の入力）と削除を出さず、理由を `.callout.is-info` で添える。ポイントは無効にし、期日とリンクは文字で出す（空は横線1本）
- 引き出しの中の URL（`.source-key`）は折り返し、引き出しの列は `minmax(0, 1fr)` にして、長い URL（2048 字）でも横にはみ出さない。狭い幅（760px 以下とタッチの画面）では、引き出しの中の小さなボタン（`.btn.is-sm`、`.link-btn`、`.edit-trigger`）とタブ（`.tab`）の押せる範囲を、見た目は変えずに 44px 四方以上に広げる
- 担当は、属性の先頭の行に、今の担当のアバター（`Avatar`。担当なしは「?」）と選択欄（`.select`。`.props dd` の中では内容の幅）を置く。名前は隣の選択欄か（読み取り専用では）文字が読むので、アバターはいつも読み上げから外す（`Avatar` の `decorative`。`aria-hidden`）。候補を読んでいる間は、選択欄に `aria-busy` を付け、「読み込んでいます」を添える（起票のダイアログも同じ）。選んだら、期日と同じく 600ms 待ってから（閉じた選択欄の矢印キーは1つ動くたびに `change` を出すので、途中の人を保存して履歴に残さないため）か欄を離れたときに、最後の値だけを `task-assign` で保存する。待っている間は書きかけに数え、閉じる／移るときに確かめる。保存の送り方（1本ずつ送り、送っている間に選び直した分は最後の選択だけを送る）と、保存した後の扱い（その欄だけを応答で入れ替え、木を読み直す）はポイントと同じ。失敗したら、選択欄を保存した値へ戻し、理由を欄の下に出す（409 の `conflict` は、完了にされていれば完了の文、そうでなければ同時に直された文）。選択肢は担当なしと、引き出しで読み込めた後に `member-list` で読む `members`（そのワークスペースに今所属している人）。今の担当が候補にいない（抜けた、無効にされた）ときは、その人を「名前（離脱済み）」の選択肢として残す（`task-detail` の `assignee.left`）。候補を読めなければ、担当なしと今の担当だけを選べ、「<担当>の候補を読み込めませんでした」と「もう一度試す」（`.btn.is-sm.is-quiet`。読めたら選択欄へフォーカスを移す）を添える。404 を受けたら、タスクを読み直して分ける。タスクが無ければ消えたときの扱い、タスクがあれば選んだ人が所属を外れたので、理由を欄の下に出し、今の値と候補を読み直す。読み直しが通信や 5xx で失敗したら、ふつうの保存の失敗の文にする。完了したタスク（API も 409）と終了したワークスペースでは、選択欄を出さず、アバターと名前（担当なしは「担当なし」）だけを出す。完了したタスクには、鍵のアイコンと「完了した<タスク>の<担当>は替えられません」を添える
- 完了の帯の下に、見本どおりのタブ（`.tabs`、`.tab`。`role="tablist"` と `role="tab"`、中身は `role="tabpanel"` でタブの名前を指す）を置く。タブは「コメント N」（N は `comment-list` が返す消していないコメントの数。読むまでは「コメント」だけ）と「変更の履歴」で、開いたときはコメントを選ぶ。選んだタブだけを Tab 順に入れ（`tabindex` の0と-1）、左右の矢印キーと Home、End で隣のタブを選んでフォーカスを移す。タブの中身は外さずに `hidden` で隠すので、書きかけのコメントはタブを切り替えても残る（引き出しを閉じた後には持ち越さない）
- 「コメント」のタブ（`TaskComments.svelte`、見本は `commentHtml`）。開いたときに `comment-list` で新しい 50 件を読み、書いた順（古い順）に `.comment` を並べる。それより前があれば、一覧の上に「前のコメントを読む」（`.btn.is-sm`）を出し、押すと前の 50 件を上に足す（読み上げに「前のコメントを N 件足しました」。読み終えてボタンが消えたら、一覧へフォーカスを移す。読めなければボタンの下に理由）。初めに読めなければ失敗の文と「もう一度試す」、読み直しに失敗したら行を残して上に失敗の文と「もう一度試す」を添える（変更の履歴と同じ）。コメントが無ければ「まだコメントはありません。」。1件は、書いた人のアバター（読み上げから外す）、見出し（`.comment-head`。今の名前、日時（ワークスペースのタイムゾーンの `YYYY-MM-DD HH:mm`。`time` 要素）、直したものは「編集済み」）と、見出しの右（`.comment-actions`）に許された操作だけの「編集」「削除」（`.btn.is-sm.is-quiet`。`can_edit` は書いた本人、`can_delete` は書いた本人とリーダー、管理者。読み上げの説明（`aria-describedby`）に名前と日時を結び、どのコメントの操作かを伝える）。本文は Markdown の部品で描き、`.comment-body` の中の `.doc-box` は枠と余白を外す。消したものは本文の代わりに「削除されました」、本人以外（リーダー）が消したら「〇〇が削除しました」（`.comment.is-deleted`。斜体の薄い文字）で、操作を出さない
- 「編集」を押すと、本文がその場で書く欄（`.edit-form` の `.textarea`。名前は「コメントを直す」、直す前の本文が入り、フォーカスと末尾のカーソルを置く）に替わり、見出しの右の操作は隠れる。「保存」で送り（`comment-update`。送っている間は欄を読み取り専用にし、ボタンを `aria-disabled` に）、通ったら本文を入れ替えて「編集済み」を付け、トースト「コメントを直しました」を出して「編集」へフォーカスを戻す。「取り消し」は送らずに戻す。直す前と同じ文（整えた後）なら送らずに戻す。直している間に別の人（リーダー）がそのコメントを消していたら（409 の `conflict`、`deleted`）、欄と書きかけの文を残したまま「このコメントは削除されました。書きかけの文は欄に残しています。」を欄の下に出し、「保存」を消して「取り消し」だけにし、一覧を読み直す（取り消すと「〇〇が削除しました」に替わる）。読み直した一覧で消えていたと分かったときも同じ知らせを出す。403 は「このコメントは操作できません。一覧を読み直しました。」で同じ扱い
- 「削除」は確認のダイアログ（`ConfirmDialog` の `danger`。「やめる」が主ボタン。文は「〇〇が YYYY-MM-DD HH:mm に書いたコメントを削除します。…」で、書いた人と日時を添える。長い名前は折り返す）を挟む。削除を送っている間は、どの行の「削除」も `aria-disabled` にする。消したら本文を「削除されました」に替え、タブの件数を減らし、トースト「コメントを削除しました」を出して一覧へフォーカスを移す。先に消されていた（409 の `deleted`）ときは「このコメントはすでに削除されています」と知らせて一覧を読み直す
- 一覧の下に新しいコメントの欄（「コメントを書く」の `.textarea`、添え書きは本文と同じ「Markdown で書けます。見出しは # が小見出しの大きさから始まります。」）と「送る」（`.composer-foot` の `.btn`）。空か空白だけなら送らずに「コメントを書いてから送ってください」、10 万字を超えるか見えない文字を含めば理由を欄の下に出す。送るのは1本ずつ（送っている間は欄を読み取り専用にし、「送る」を `aria-disabled` に）。通ったら欄を空にし、書いたコメントを一覧の末尾に足してそこまでスクロールし、件数を増やす。失敗したら文を欄に残して理由を欄の下に出す（通信の失敗と 5xx は「コメントを送れませんでした。書いた文は残しています。もう一度試してください。」、閉じていれば「終了した<ワークスペース>には書き込めません」で枠を読み直す、404 はタスクが消えたので引き出しを閉じる）。閉じた後に返った応答も、通ったか失敗したかをトーストで知らせる
- 新しいコメントの欄と「送る」は、一覧を読めてから出す（読み込み中と読めなかった間は出さない）。タブの件数も、読めた値から始め、書いたら足し、消したら引く。書いた（作った、直した、消した）行は、それより前に始めた一覧の読み直しの応答に重ねて残す（古い応答で、送ったコメントや直した本文が消えない）。読み直しでは、「前のコメントを読む」で足した古い行を、新しい 50 件と地続きのときだけ残し、地続きでなければ捨てて応答の続きから読み直す（抜けた区間を作らない。`src/lib/comment-thread.ts`）
- 一覧と欄の領域（`.thread`）は `role="region"` で「コメントの一覧」の名前を持ち、前のコメントを読み終えたとき、読み直せたとき、コメントを消したときのフォーカスの置き先にする。変更の履歴のタブの中身（`.tab-panel`）も、`.thread` と同じだけタブの線から空ける
- 終了したワークスペースでは、コメントを読めるが、新しいコメントの欄と「編集」「削除」を出さない（API も 409 の `workspace_closed` で断る）。開いている間に書いていた新しいコメントの書きかけがあれば、終了が分かった後も欄を読み取り専用で残し、「終了した<ワークスペース>には送れません。書きかけの文は写して残せます。」を添え、「送る」を出さない
- 「変更の履歴」のタブは `task-history` の結果を `.history` の行で新しい順に出す。読むのは、引き出しでタスクを読み込めたときと、引き出しで保存（欄の保存と担当の保存）が通った後と、断られてタスクの今の値を読み直したとき（409 の競合など。別の人の変更を履歴にも出す）で、読み直している間は前の行を残し、タブの中身に `aria-busy` を付ける。初めに読んでいる間は「読み込んでいます」（読み上げには、タブの中身に常に置いた `role="status"` の領域で伝える。「さらに読む」で読んでいる間と、足した件数（「N 件を足しました」）も同じ領域で伝える）、読めなければ失敗の文と「もう一度試す」（404 はタスクが消えたので、「もう一度試す」を出さず、詳細が 404 のときと同じくトーストで知らせて閉じる。読み直している間も失敗の表示を残し、ボタンは `aria-disabled` にして「読み込んでいます」に替える。読めたらタブの中身（`tabindex="-1"`）へフォーカスを移す）、行が無ければ「まだ変更はありません。」。行を出した後の読み直し（保存の後）に失敗したら、行は残し、一覧の上に小さく失敗の文と「もう一度試す」を添える。先頭を読み直している間は「さらに読む」を押せなくし（`aria-disabled`）、その前に始めた続きの応答は捨てる。1行は、日時（ワークスペースのタイムゾーンの `YYYY-MM-DD HH:mm`。`time` 要素）、変えた人のアバター（読み上げから外す）と今の名前（変えた人がいない行は「定期処理か運用者」でアバターなし）、操作（作成、変更、完了にした、削除した）で、その下に欄ごとの行（`.history-changes`）を並べる。作成は作ったときの空でない値を、変更は「前 → 後」を、完了と削除は操作だけを出す。本文は値を出さず「本文を直した」、表に無い欄は「そのほかの欄を直した」。列の名前は `src/lib/task-history.ts` の表で辞書の言葉にする（タイトル、ポイント、期日、リンク、本文、担当、親の<ストーリー>、区分、リポジトリ、今日やる。言葉づかいを切り替えると替わる）。人と親と区分の値は、変えた時点の名前で、名前が空なら「不明」。長い名前と値は行の中で折り返す。空の値は、ポイントは「未見積もり」、担当は「<担当>なし」、それ以外は「なし」。50 件を超える履歴は「さらに読む」で続きを足す。保存の後の読み直しは先頭の 50 件に戻し、「さらに読む」で足した行は外れる（新しい行は先頭に入るので、読み直した先頭を見れば足りる。足した行の続きを保つと、先頭と続きの境目がずれて行が抜けうる）（読み終えてボタンが消えたら、タブの中身へフォーカスを移す）。続きが読めなければ、ボタンの下に理由を出す。削除したタスクは引き出しを開けず、`task-history` も 404 を返すので、削除の行は出ない（リーダーと管理者の変更の履歴の画面で出す）
- リポジトリは、期日の下に起票と同じボタンの並び（`RepositoryPicker`）で置き、選んだら保存する（ポイントと同じく1本ずつ送り、送っている間に選び直した分は最後の選択だけを送る）。選択肢は直せるときだけ `category-repository-list` で読み、読んでいる間はリポジトリの並びと区分の選択欄を `aria-busy` にして「読み込んでいます」を出す。読めなければ「なし」と今の値だけを選べ、担当の候補と同じく「<区分>とリポジトリの一覧を読み込めませんでした。」と「もう一度試す」（`.btn.is-sm.is-quiet`。読めたらリポジトリの今の選択へフォーカスを移す）を添え、文を両方の欄の `aria-describedby` に結ぶ。終了したワークスペースでは `.segmented.is-readonly` で選んだ値の色を保つ。
- 区分は、親のないタスクでは選択欄（`.select`）で、担当と同じく選んで少し待ってから（か欄を離れたときに）最後の値だけを保存する（待っている間は書きかけに数える）。親のあるタスクでは、引き継いだ区分（無ければ<区分>なし）を文字で出し、「親から引き継ぎ」（`.props-note`）を添える。終了したワークスペースでは文字だけを出す。送るまでに区分かリポジトリが削除されていた（404 で、タスクはある）ときは、欄の下に理由を出し、選択肢を読み直す。親の下へ移されていて断られた（409 の `has_parent`）ときは、読み直した値で理由を出す。
- この版で出さない欄（決まった欄、感謝、添付ファイル（コメントの添付ファイルを含む）、完了を戻す操作）は、本番の引き出しに置かない。見本には残してあり、それぞれの機能の Issue で本番に足す

## 見本を作って補ったこと

画面にするために決めたこと。要件定義に書いていないもの。

- ストーリーは別の画面を持たず、バックログの木の行から開くダイアログで作り、直す（親のないストーリーの居場所が、エピックの画面には無いため）。配下のタスクと完了の操作は木の行に並べる。エピックの下のストーリーは、バックログの木のエピックの行の配下に並べる。エピックの画面での見せ方は、エピックの画面の Issue（#65）で決める。
- エピックの作成と、タイトル、本文、期日、リンクの変更は、エピックの画面より先に、バックログの木から開くダイアログで行う（依頼主は作った人、クリア報酬は中で作る）。木の題から何を開くかは、エピックの画面（#65）で見直す。
- 組織の単位の変更の履歴（組織の作成、管理者の指名と解除、ユーザーの無効化と有効化、組織の設定の変更、運用者の操作、ワークスペースの作成と終了と再開）は、組織の管理の画面の中に出し、別の画面を持たない。所属などワークスペースの中の変更は出さない。
- スプリントの終了は、最終日の前でも押せる。最終日を過ぎたら終了を促す。
- 受信箱では、まとめて選んでバックログへ入れたり、アーカイブしたりできる。
- 完了の記録は CSV で書き出せる。
- 配分の合計が100%を超えた月の知らせは、自分の設定の画面の先頭に出す。
- 届いた招待は、ログインした直後（組織の選択。組織ごとの招待の画面へのリンク）と自分の設定の画面に出す。承諾と辞退は組織ごとの招待の画面（`/<slug>/invitations`）で行う。
- 添付ファイルは、画像と動画を縮小した絵で並べ、それ以外を1行ずつ並べる。押すとプレビューが開き、そこからダウンロードと削除ができる。
- タスク、エピックは添付ファイルの欄にドラッグできる場所を持つ。ストーリー、起票、コメントは場所を取らないよう「ファイルを添付」のボタンだけにする。
- 本文に差し込んだ画像のファイルが消えていたら、その場所に「ファイルが見つかりません」と出す。
- 組織の管理では、添付ファイルの合計に加えて、ワークスペースごとのファイル数と合計を出す。どこを片付ければよいかを管理者が見つけるため。
- 運用の画面の上限の変更は、値段の段階（15人と30 GB、50人と100 GB）から選ぶか、人数と容量の値を入れる。
- 人数が上限に達した組織では、招待の画面に上限に達したことと、管理者に相談するよう出し、新しい人の招待のボタンを押せなくする。すでに組織にいる人は、上限に達していても招待できる。
- 招待と管理者の指名で人を指す欄は、先にログインの手段（GitHub か Google）を選び、選んだ手段に合わせて欄の名前と例を差し替える。Google で招待すると、招待の URL とコピーのボタンをダイアログで出し、この画面を閉じると二度と出ないことと期限（14日）を添える。招待の一覧には手段と、Google の招待の期限を出す。
- ログインの画面には、招待の URL から開いたときの見本を置く。招待された Google アカウントでログインするよう促し、使えない URL（期限切れ、取り消し済み、別のアカウント）は理由を分けずに伝える。招待の URL を開く画面は `/invite`（枠の外。見出しは「Scrum Guild への招待」）で、秘密を `location.hash` から読んですぐ URL から消し、「Google でログイン」のボタンを押すまでログインを始めない。秘密の形が合わない URL は、ボタンを出さずに使えない旨を出す。ログインを始められなかったときは `/login?error=invite` へ移り、同じ文言を出す。
- Google のボタンは Google のブランドの決まりに合わせる（下の「Google のボタン」）。
- 初めて使う人には、自分の今日の先頭に「最初にやること」をロール（一般、リーダー、ワークスペースのない管理者）ごとに出す。済んだかは今のデータ（起票したタスク、今日やるの印、招待、スプリント、接続、ワークスペース、組織の休日）から決めるので、閉じた印は DB に要らない。必須の手順がすべて済んだら消える。必須は、一般が「自分のタスクを用意する」（起票か接続の登録のどちらかで済む）、リーダーが「メンバーを招待する」と「バックログに最初のタスクを入れる」、管理者が「最初のワークスペースを作る」。今日やるの印、スプリント、接続、組織の休日、管理者からの招待は、使わない人や1人で使う組織もあるため任意とし、消すかどうかの判定から外す。
- 空の一覧には、何が出る場所かと次にやることを書き、自分で起こせることがあればその画面へのボタンを1つ添える。自分の今日では、今日やる以外の区分は空なら出さない。
- ワークスペースがまだない管理者のメニューには、組織の画面（自分の今日、通知、自分の設定、組織の管理）だけを出す。
- AI のアシスタントは、上の帯の左端にボタンを置き、どの画面からも `Ctrl+K` で開く。運用者の画面には出さない。パレットで頼み、続けて話したいときだけ横の欄へ移す。変える頼みごとの確認は行ごとに外せ、5 件を超えると畳み、残りを開くまで実行できない。横の欄は 1500px 以上の画面でだけ本文を左へ寄せる。決めたことは `docs/ai.md` の「画面の形」。

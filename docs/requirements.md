# 要件定義

状態: 初版（未決の論点が残っている）

## 目的

Backlog や GitHub に散らばった自分のタスクを1か所に集め、次の3つを1つの道具で薄く回す。

- 実行: 今日と今週にやるタスクを選んで進める
- 計画: エピック、ストーリー、ポイントで数週間先まで見通す
- 記録: 何をいつ終えたかを区分と月で残し、振り返りと請求の根拠にする

## 前提

- 正本は scrum。Backlog と GitHub はタスクの入口として使う。
- 初版の利用者は1人。ただしユーザーとワークスペースの概念は最初から持ち、チームでの共有に広げられる形にする。
- OSS として公開する。利用者が自分の Cloudflare アカウントに立てられることを前提にし、特定の個人や会社の設定をコードに持たない。

## 技術の前提

| 項目 | 決定 |
| --- | --- |
| 稼働先 | Cloudflare Workers |
| DB | Cloudflare D1 |
| API | Hono |
| 画面 | Svelte の SPA（Vite でビルドし、Workers Static Assets で配る） |
| 認証 | GitHub OAuth |
| 定期処理 | Cron Triggers |

API（`/api/*`）、画面の配信、定期処理を1つの Worker にまとめる。デプロイの単位は1つで、利用者は D1 の作成、シークレットの登録、デプロイの3手順で立てられる。

## 概念

| 概念 | 何か |
| --- | --- |
| ワークスペース | タスクの集まりの単位（現行の「仕事」と「プライベート」のボードに当たる）。メンバーを持つ |
| 接続 | ワークスペースに登録した取り込み元（Backlog のスペース、GitHub のアカウントや組織） |
| エピック | 期日のある成果。ストーリーが複数入る |
| ストーリー | エピックの中で、1スプリントで終わる確認できる区切り |
| タスク | 実際の作業。手で作るか、取り込み元から取り込む |
| スプリント | 月曜始まりの期間 |
| 区分 | エピックに振る分類（保守、追加案件など）。一覧はワークスペースごとに利用者が定義する |

取り込んだタスクも手で作ったタスクも、同じ1つのタスクとして DB に持つ。違いは取り込み元への参照を持つかどうかだけにする。

## メンバーと権限

ワークスペースのメンバーは、オーナーとメンバーのどちらかのロールを持つ。

| ロール | できること |
| --- | --- |
| オーナー | メンバーができることに加え、ワークスペースの設定（列、区分、タイムゾーン）、接続、メンバーの管理 |
| メンバー | タスク、ストーリー、エピック、スプリントの操作 |

## 取り込み

- 対象は Backlog の課題、GitHub の Issue、PR、レビュー依頼。
- Cron Triggers で定期的に取り込み元を読み、DB に保存する。画面を開いたときに取り込み元を叩かない。
- 取り込み後は、取り込み元が持つ属性（タイトル、取り込み元での状態、期限、URL）だけを同期で更新する。scrum が持つ属性（列、スプリント、親、ポイント、期日）は同期で書き換えない。
- 取り込んだタスクをスプリントに入れたときの列は、接続ごとに設定する「取り込み元の状態から列への対応」で決める。対応のない状態は先頭の列に置く。完了の列は対応先にしない。
- 取り込み元で完了したタスクは自動で完了にせず、通知を出す。完了にするかは利用者が決める。
- 取り込み元には書き戻さない。
- 接続はワークスペースに属し、登録したメンバーの認証情報でその人の担当分を取り込む。取り込んだタスクは登録したメンバーが担当になり、ワークスペースの全員が見られる。
- 接続の認証情報（Backlog の API キーなど）は暗号化して DB に保存する。
- 取り込み元は共通の型で実装する。型が持つのは、接続の設定項目、取り込み元からの取得、取り込み元の状態の一覧、タスクへの変換。Backlog と GitHub もこの型で実装し、新しい取り込み元はこの型の実装をリポジトリに足して加える。

## 機能

### 初版

- バックログ: エピック、ストーリー、タスクの木で並べる
- スプリント: 月曜始まりで長さは1〜4週。その回だけ伸ばすこともできる。終わらなかったタスクは次へ持ち越す
- 列: ワークスペースごとに利用者が定義する。完了の列だけは固定で持つ
- ポイント: タスクにフィボナッチ（1、2、3、5、8、13）で振り、階層ごとに合計を出す
- 期日: タスク、ストーリー、エピックに振る
  - 表示する期日は1つ。scrum で振った期日があればそれを、なければ取り込み元の期限を出す
  - 期日を過ぎたら赤、今週（月〜日）中なら橙で出す。完了したタスクは色を付けない
  - 期限を運用していない取り込み元のために、接続ごとに取り込み元の期限を無視する設定を持つ
  - 今日と今週の判定は、ワークスペースに設定したタイムゾーンで行う
- 区分: エピックに振り、配下のストーリーとタスクが引き継ぐ
- 計上月: 月ごとに計上する区分では、タスクに計上月を持つ。既定は完了した月
- PR と課題の紐付け: PR の本文の参照から課題と自動で関連付け、課題の付け先を引き継ぐ
- リンク: エピックと手で作ったタスクに資料の URL を1つ
- 完了日の記録: タスクを完了にした日時を保存する

### 後回し

- 振り返りの画面（週ごとの完了ポイントと平均）。完了日は初版から記録するので、後から画面だけ足せる
- GitHub リポジトリのディレクトリにある Markdown の取り込み（1ファイルを1タスクにする）。それまでは手で作るタスクで代える

## Non-Goals

- 取り込み元への書き戻し
- 取り込み元で完了したタスクを自動で完了にすること
- 現行 kanban からのデータ移行
- Cloudflare 以外への対応（初版）

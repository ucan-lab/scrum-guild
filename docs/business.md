# Team Leveling をサービスにする方針

状態: 方針。値段と目安は仮で、ベータで確かめて直す。

## 決めたこと（2026-10-21）

- OSS をやめ、自分たちで運用するサービスにする。リポジトリは private のままにし、権利はすべて ucan-lab が持つ（`LICENSE`）。
- 稼働先は Cloudflare（Workers と D1）だけに絞る。Docker などで自分で立てる道は持たない。
- 1つのアプリと1つの D1 に複数の王国（顧客）を入れる。顧客ごとに Worker と D1 を立てる形は、顧客が増えるたびに立てる手間がかかるため選ばなかった。初版では王国は運用者が作り、申し込みと課金はアプリの外に置く。

## 経緯

はじめは自分のチームのためのタスク管理を OSS（MIT）で作り、立てる人が自分の Cloudflare か Docker に立てる前提だった。副収入にし、手応えがあれば事業にしたいと考えたため改めた。

- OSS のために背負っていた重さ（2つの稼働先、4つのアダプター、両方で通る SQL だけの縛り、公開前の点検）がなくなり、1人で作る量が減る。
- 失うのは、データを預けたくない会社に「自分で立てられる」と答える道と、OSS としての見つけてもらいやすさ。前者は、預かるデータを安全に扱うことで答える。
- 後で公開したくなったら、ソースは見られるが同じサービスを売ることを禁じるライセンス（FSL など）も選べる。MIT で一度出したものは取り消せないため、先に閉じておく。

## 誰が払うか

Backlog と GitHub を併用する、日本の受託開発や SES のチーム。「記録」（何をいつ終えたかを区分と月で残し、CSV で書き出す）が請求の根拠を作る手間を減らす。

## 値段の考え方

- 人数ごとではなく、王国ごとの定額か、ワークスペース数の段階制にする。ゲームの仕組みは全員が入って効くので、人数で課金して一部の人だけ入れる使い方を招かない。
- 仮の値段: 小さい王国（〜10人）は月 3,000円、標準（〜50人）は月 10,000円。添付ファイルの合計の上限は、小さい王国が 10GB、標準が 50GB。R2 の保存料は 50GB でも月に数百円に収まり、上限は費用よりも使いすぎを止めるために置く。
- 原価は Workers Paid（月 $5〜）と使った分が中心で、小さく始めても赤字になりにくい。

## 進め方

1. 初版を作る。まず自分のチームで使う。課金はまだ作らない。
2. ベータ（副収入）。知り合いのチームなど 5〜10 の王国に提供する。支払いは Stripe。請求書払いの求めには、はじめは手で請求書を出す。目標は月に数万円。
3. 事業にするか決める。目安は、有料の王国が 30 以上、月の解約率が 3% 未満、紹介や問い合わせで自然に増えていること。

事業にするときに要るもの: 王国を立てる手順の自動化、セキュリティチェックシートへの回答、インボイス制度に合う請求、利用規約、プライバシーポリシー、秘密保持の取り決め、必要なら法人化。

## 設計に入れておくこと

- 課金と顧客の管理はアプリの外に置き、アプリには入れない。
- 取り込み元（Backlog、GitHub）の認証情報は暗号化して持ち、解約したときの消し方を決める。
- 取り込み元の本文は既定で預からない。タイトルなどタスクとして扱うのに要る属性だけを持ち、本文も預けたい王国だけが王国の設定で選ぶ。顧客のデータを外部のサービスへ複製できない受託や SES のチームでも入れやすくし、セキュリティチェックシートで「本文を預からない」と答えられるようにする。
- GitHub のログインは、共通の1つの OAuth App にする（2026-10-22 に決めた。`development.md` の「GitHub のログインと取り込み」）。

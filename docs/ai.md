# AI でタスク管理を軽くする

状態: 案。決まったものは `requirements.md` と `data-model.md` に移す。

## ねらい

要件定義の目的にある「リーダーが詳細を書いたり、メンバーから聞き取って書き足したりする手間を減らす」を、ゲームの仕組みに加えて AI でも進める。AI は下書きを出すまでにとどめ、決めて書き込むのは人にする。

## できること

### 1. ストーリーをタスクに分ける

- エピックの画面で、ストーリーの「タスクに分ける」を押すと、ストーリーのタイトル、受け入れ基準、本文、エピックの本文から、タスクの案を出す。
- 案はタスクごとに、タイトル、決まった欄の下書き、ポイントの案、そう分けた理由を持つ。
- 案は一覧で示し、人が選んだり直したりしてから「この内容で作る」で作る。作ったタスクはストーリーの配下の末尾に置く。
- 配下にタスクがあるストーリーでも使え、すでにあるタスクと重ならない案だけを出す。

### 2. ポイントの案を出す

- タスクの詳細と計画の画面で、未見積もりのタスクにポイントの案を出す。計画の画面では未見積もりのものをまとめて出せる。
- 案の根拠に、同じワークスペースの完了の記録から似たタスクとそのポイントを数件示す。過去の記録が少ないうちは、根拠がないことを示す。
- ポイントは請求の根拠になるので、案を自動で書き込まない。人が選んで初めて振られる。

### 3. 議事録からストーリーを起こす

- バックログの画面の「議事録から起こす」で、議事録の文を貼り付けると、エピック、ストーリー（受け入れ基準を含む）、タスクの木の案を出す。
- すでにあるエピックやストーリーに入るものは、その下に足す案として示す。
- 案は木で示し、人が選んだり直したりしてから作る。作ったものはバックログの末尾に置く。
- 議事録の文は保存しない。残したいときは、作ったエピックやストーリーの本文に人が貼る。

### 4. 画面から Claude に頼む

- どの画面からも開ける横の欄（アシスタント）で、言葉で質問したり操作を頼んだりできる。
  - 質問の例: 「今のスプリントで遅れそうなタスクは」「田中さんの今月の積載量は」「このレイドの残りは」
  - 操作の例: 「このストーリーのタスクを全部今のスプリントに入れて」「期日が過ぎたタスクを一覧にして、担当に今日やるを付けるよう頼むコメントを書いて」
- アシスタントは、開いている画面（ワークスペース、エピック、スプリントなど）を前提として受け取る。
- アシスタントができる操作は、頼んだ人が画面でできる操作と同じ範囲だけにする。権限は API が検査し、AI のために別の権限を設けない。
- 読むだけの操作はそのまま行う。書き込む操作は、何をどう変えるかを確認の欄で示し、人が「実行」を押してから行う。まとめて変えるときは1回の確認で1つのトランザクションにする。
- 会話はブラウザの中にだけ持ち、DB に残さない。画面を閉じたら消える。

## 作りの方針

### 操作の定義を1か所に持つ

アシスタントの道具（tool use）、公開する API、MCP（`ideas.md` の「外部からの操作」）を、同じ操作の定義から作る。操作ごとに、名前、説明、入力の型、読むだけか書き込むか、要る権限を1つの定義に持ち、Hono の API、アシスタントの道具、MCP の道具を、その定義から作る。こうすれば、画面でできることとアシスタントにできることがずれない。

### Claude の呼び出し

- Worker から Anthropic の Claude API を直接呼ぶ。TypeScript の公式 SDK（`@anthropic-ai/sdk`）を使う。
- モデルは wrangler の設定に持つ。既定は `claude-opus-5-5`。機能ごとに変えられるようにし、案を出すだけの軽い処理を安いモデル（`claude-haiku-5-5` など）に替えるかは、ベータで質と費用を見て決める。
- タスクの案、ポイントの案、議事録からの木は、構造化出力（`output_config.format`）で型の決まった JSON を受け取り、Worker で検証してから画面に返す。
- アシスタントは tool use の往復を Worker で回し、応答は画面へストリーミングで流す。
- システムプロンプトと道具の定義は固定にし、プロンプトキャッシュを効かせる。
- API キーはシークレットに持ち、運用の手順書のシークレットの一覧に足す。

### 取り込んだ内容は指示として扱わない

取り込んだ GitHub の Issue や PR には、チームの外の人が書いた文が入る。それを AI に渡すと、文に紛れた指示で AI が意図しない操作をしようとすることがある（プロンプトインジェクション）。次で防ぐ。

- 書き込む操作は必ず人の確認を挟む（上の「画面から Claude に頼む」）。
- アシスタントにウェブの取得など外へ出る道具を持たせない。
- 取り込んだ本文はデータとして囲んで渡し、システムプロンプトで指示として扱わないよう伝える。

### 費用の上限

- 王国ごとに月の利用の上限（トークン数）を持ち、超えたらその月は AI の機能を止めて知らせる。上限の値は運用者が王国ごとに決める。
- ユーザーごとのレート制限を設ける（要件定義の「アプリ側のレート制限」に AI を足す）。
- 呼び出しごとに、王国、ユーザー、ワークスペース、機能、モデル、入力と出力のトークン数、日時を記録する。中身（プロンプトと応答）は記録しない。

## 要件定義と当たるところ

| 要件定義の決まり | 当たり方と案 |
| --- | --- |
| 外部への通信は取り込み元と GitHub のログインだけ | Anthropic の API が加わる。要件を「AI の機能を有効にした王国では Anthropic にも送る」に改める |
| 顧客のデータを預かる体制が未決（`business.md`） | タスクや議事録の中身を Anthropic に送ることになる。管理者が王国の設定で AI の機能を有効にするまで使えないようにし、有効にする画面で送る先と送る内容を示す。Anthropic の API でのデータの扱い（学習に使うか、保持の期間）は採用の前に規約で確かめ、利用規約とプライバシーポリシーに書く |
| 起票と詳細の経験値は、メンバーが自分から書くことを促すためのもの | AI の案から作ったタスクにも経験値を付けると、案を出して作るだけで経験値が貯まる。案: AI の案から作ったタスクには起票の経験値を付けない。決まった欄を AI の下書きのまま埋めたものは詳細の経験値を付けず、人が書き直した欄だけを数える。完了の経験値は変えない |
| ポイントは見積もりと請求の根拠 | 案を自動で書き込まない（上の「ポイントの案を出す」） |
| 変更の履歴は誰がいつ何を変えたか | AI を通した操作は、頼んだ人の操作として残し、AI を通したことの印を添える |

## データモデルに足すもの（案）

| 表 | 足すもの |
| --- | --- |
| `kingdoms` | `is_ai_enabled`（既定 0）、`ai_monthly_token_limit` |
| `tasks` | `created_via`（`manual`、`ai`）。起票の経験値の判定に使う |
| `task_field_values` | `filled_via`（`manual`、`ai`）。詳細の経験値の判定に使う。人が直したら `manual` にする |
| `change_logs` | `via`（`manual`、`ai`） |
| `ai_usages`（新） | `kingdom_id`、`user_id`、`workspace_id`、`feature`、`model`、`input_tokens`、`output_tokens`、`created_at` |

## 画面に足すもの（案）

- 画面の上に重ねるもの: アシスタントの横の欄。ヘッダーから開く
- エピックの画面: ストーリーの「タスクに分ける」と案の一覧
- タスクの詳細、計画: ポイントの案
- バックログ: 「議事録から起こす」のダイアログと案の木
- 王国の設定: AI の機能を有効にする欄、送る先と内容の説明、今月の利用量
- 運用: 王国ごとの AI の利用の上限と今月の利用量

ゲームの言葉では、アシスタントを「ギルドの書記」などと呼ぶ案がある。

## 値段

AI の費用は使った分だけかかる。王国ごとの定額（`business.md`）に月の上限まで含めるか、AI を別の段にするかを、ベータで実際の利用量を見て決める。

## 進め方の案

1. 初版の土台で、操作の定義を1か所に持つ作りにしておく（後から道具や MCP を足せるように）
2. 「ストーリーをタスクに分ける」と「議事録から起こす」。案を出して人が選ぶ形で、書き込みの危うさが小さい
3. 「ポイントの案を出す」。完了の記録が貯まってから効く
4. アシスタント。操作の定義が揃い、確認の欄の作りが固まってから

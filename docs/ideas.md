# アイディア

要件として決める前のアイディアを書き留める。採用が決まったものは `requirements.md` に移す。

## 外部からの操作

- 遠隔の MCP（Worker の `/api/mcp`）で操作できる。手元の AI から使う stdio の MCP（`sg mcp`）は `requirements.md` に移した
- 画面上から Claude などの AI に指示して操作できる。案は `ai.md`

## AI

- ストーリーのタスク分割、ポイントの案、議事録からのストーリー作成、画面からの Claude の呼び出し。案は `ai.md`

## デイリークエスト

- タスクと関係のない毎日の習慣（メールの確認、問い合わせの確認、日報を書くなど）を設定できる

## ゲームらしさ

- 案内役のキャラクター（ギルドの受付係など）が、初めての操作やレベルアップの場面で声をかける。テーマごとの絵柄（シンプル、中世風、現代風で描き分けるか）と、スクラムの言葉のときに出すか、どう呼ぶか、出す回数と消し方（閉じる、二度と出さない設定）、原則 4（演出は短く1回で終わる）との関係が論点
- 効果音（クリア、レベルアップ、完了の印）。既定はオフで、本人が自分の設定でオンにする。素材（自作か使える条件の素材か）と、鳴らす場面をどこまで絞るか、設定をどこに持つか（ユーザーの設定か端末ごとか）、OS の設定（`prefers-reduced-motion` など）に合わせるかが論点

## ゲームの言葉

画面の言葉をゲームの言葉にできるようにする案。選べた頃の用語の対応を残す。言葉づかいを選ぶ口を戻すときは、組織の設定とワークスペースの作成のどちらで選ばせるか、選んだ言葉づかいをどの範囲（組織、ワークスペース）に効かせるかが論点。辞書（`src/shared/vocabulary.ts`）はスクラムの言葉の文字列だけを持つので、戻すときは、ゲームの言葉の文言を辞書に足すところから始める。

| スクラムの言葉 | ゲームの言葉 |
| --- | --- |
| 組織 | 冒険者ギルド |
| 管理者 | ギルドマスター |
| ワークスペース | パーティ |
| リーダー | パーティリーダー |
| メンバー | 冒険者 |
| 受信箱 | 届いた便り |
| アーカイブ | 保管庫 |
| バックログ | 掲示板 |
| エピック | レイド |
| ストーリー | 達成目標 |
| タスク | クエスト |
| スプリント | 遠征 |
| スプリントゴール | 遠征の目的 |
| バーンダウンチャート | ボス戦 |
| 完成の定義 | パーティの掟 |
| エピックを作った人 | 依頼主 |
| エピックに参加するメンバー | 討伐隊 |
| エピックに自分から参加する | 受注 |
| エピックの完了 | レイドのクリア |
| 列 | 行程 |
| 完了の列 | 完遂 |
| 接続 | 便りの経路 |

| 詳細 | 手配書 |
| 受け入れ基準 | 達成条件 |
| 期日 | 期限 |
| ポイント | 難易度 |
| 担当 | 担い手 |
| 区分 | 系統 |

経験値、クリア報酬、感謝はゲームの仕組みにだけある語で、スクラムの言葉に対応する語を持たない。表にない語（コメント、通知、設定、履歴などの画面の部品）は、どちらの言葉づかいでも同じ語を使う。

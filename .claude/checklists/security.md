# セキュリティ（言語に依存しないもの）

## 認証、認可

- 保護すべきルートに認証チェックが無い
- 他人のリソースの ID を指定するとアクセスできる（所有者の確認漏れ）
- パスワードを平文で比較している。低速で salt 付きの関数（Argon2id、scrypt、bcrypt、PBKDF2）以外でハッシュしている
- JWT の署名や有効期限を検証していない
- 状態を変えるエンドポイントに CSRF 対策やレート制限が無い
- パスワードリセットのトークンが使い捨てでない、または期限が無い

## 入力と出力

- SQL、シェルコマンド、ファイルパスに、ユーザー入力を文字列連結で入れている
- XML パーサーが外部実体を読み込む設定になっている
- CORS でリクエストの Origin をそのまま反射し、`Access-Control-Allow-Credentials: true` を返している（認証情報を伴わない公開 API の `*` は対象外）

## 秘密情報

- API キー、パスワード、トークン、接続文字列をソースに直書きしている
- パスワード、トークン、個人情報をログに出している
- 本番でデバッグモードやスタックトレースが有効になる設定

## 設定の既定値

- 署名、暗号、セッションの鍵に既定値がある（`env('APP_KEY', 'dev-secret')`、`process.env.SECRET || 'changeme'`）。設定漏れのまま起動してしまうので、未設定なら起動を止める
- 未設定のときに緩い側へ倒れる（`ALLOWED_ORIGINS || '*'`、認証を必須にするフラグの既定が false、デバッグの既定が true）
- セキュリティ用の数値パラメータの 0 や -1 が無制限を意味する（`max_attempts=0` で試行回数が無制限、`lifetime=0` で期限が無期限）。上限と下限の両方を検査しているか

## 並行処理

- 残高や在庫を確認してから更新するまでの間にロックが無い（トランザクション内で `SELECT ... FOR UPDATE` を使うか、`UPDATE ... SET stock = stock - 1 WHERE stock >= 1` のように条件付きで更新して更新行数を確かめる）

## 誤検知として扱うもの

- `.env.example` の値
- テスト用と明記された認証情報
- 公開前提の API キー
- パスワード以外の用途（チェックサムなど）での SHA256 や MD5

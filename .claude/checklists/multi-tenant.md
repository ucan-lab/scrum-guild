# 王国の分離

全王国（顧客）が1つの D1 と1つの R2 のバケットに入る。王国をまたいでデータが見えることは、このサービスで一番重い事故として扱い、確信が低くても指摘する。決まりは `docs/data-model.md` の「決まりごと」と「データベースの分け方」、`docs/requirements.md` の「王国と運用者」。

## 絞り込み

- 王国の中の表の行を、ID だけで引いている、書き換えている、消している（`kingdom_id` か、王国を確かめた `workspace_id` で絞る）
- URL やリクエストの body に入った `workspace_id`、`epic_id`、`task_id` などを、リクエストの王国（URL の slug）のものか確かめずに使っている
- 親の ID を確かめたことを根拠に、子の ID を絞らずに使っている（`/workspaces/:w/tasks/:t` で `:w` を確かめても、`:t` が `:w` のものとは限らない）
- 王国の中の表を、王国の DB を選ぶ入口の関数を通さずに読み書きしている
- 王国をまたいで読む処理（ログインできるか、ログイン直後の王国の選択、届いた招待の一覧、初めてのログインでの `users.account_id` の補完）を、決まった1つの関数の外に書いている
- 一覧や集計で、王国の絞り込みが JOIN の片側にしか付いていない

## 入れるか

- 停止した王国に入れる。停止した王国の定期処理（取り込み、日をまたぐ処理）が止まっていない
- その王国の `users` が無効になった人や、ワークスペースから外れた人が、セッションが残っているだけで入れる（王国に入れるかはリクエストのたびに確かめる）
- 運用者が、管理者として指名されていない王国の中のデータを読める。運用者の画面に、決まった数値（ユーザー数、ワークスペース数、タスク数、添付ファイルの合計、最後に使われた日時）以外を出している

## 添付ファイル（R2）

- R2 のキーの先頭が王国の ID になっていない
- R2 のキーをリクエストから受け取って、そのまま読んでいる、消している（`attachments` の行を王国で絞って引き、そのキーを使う）
- バケットを公開して URL で配っている（Worker で権限を確かめてから返す）
- 容量の上限を王国ごとに数えていない

## 定期処理

- 王国ごとの処理で、1つの王国の失敗が他の王国の処理を止める
- 前の王国の値を持ち越して次の王国の処理に使っている（ループの外の変数、使い回しの配列）

## 状態を持つもの

- モジュールの最上位の変数や `Map` に、王国の中のデータを王国の ID を含まないキーで持っている（同じ isolate の別の王国のリクエストから見える）
- 取り込み元の認証情報を、王国とワークスペースで絞らずに引いている

## ログと応答

- ログに、本文、コメント、取り込んだ内容、認証情報、トークンを出している
- エラーの応答に、別の王国の行があることを示す情報を出している（他の王国の ID を指定したときは、存在しないときと同じ 404 にする）

## テスト

- 新しい API の操作に、別の王国の ID で呼ぶと 404 になることを確かめるテストが無い
- 王国の分離のテストが、同じ王国の中のデータだけで組まれていて、別の王国の行を用意していない

# 画面

前提の決まりは `docs/design.md`（デザイン原則、どのテーマにも共通すること、テーマごとの違い、飾りの決まり、デザインシステムの構成）。`docs/design.md` とデザインシステムに決まりがあれば、そちらを優先する。

## 残すもの

- 差分の目的と関係なく、既存の内容、数値、操作、流れ、検索や絞り込みなどの動作を変えている、または消している
- 画面に置いたのに動かない機能、ダミーの値、与えられていない事実（件数、実績、条件）を足している

## 文字と余白

- 最初に読みたい情報と主な操作が、文字の大きさ、太さ、位置で他より強くなっていない。強調が多すぎて要所が埋もれる
- 操作や一覧が中心の画面で、見出しが大きすぎる。余白でなく枠や線を重ねて区切っている
- 文字の大きさを `design/tokens.css` の段（`--text-*`）から選んでいない。役割と段が合っていない（画面の見出しは `--text-2xl`、節の見出しは `--text-xl`、本文は `--text-md`、補足は `--text-sm` か `--text-xs`）
- 文字の大きさで押せる範囲を決めている（押せる範囲は文字と別に、余白で確保する）
- 同じ役割の文字、左右の端、数値の位置が揃っていない
- 関係する情報が離れている。別のまとまりとの間に余白が無い
- 比べる内容に合わない組み方（項目を横に比べるのにカードを並べる、1件ずつ読むのに表にする）
- トークンの書体を使っていない。数字が斜体や装飾のある字形になっている（キー、日付、ポイントは IBM Plex Mono）
- `design/icons.js` の外からアイコンを持ち込んでいる。線の太さが揃わない

## デザインシステム

- 画面ごとの CSS を持っている（`.svelte` の `<style>`、`design/*.html` の `<style>` や `style=""`）。足りない部品は `design/components.css` とカタログ（`design/index.html`）に先に足す決まり
- 部品の CSS で色、書体、余白、角、影を直に書いている。`design/tokens.css` の変数を使う
- 部品を足したのに、カタログに見本と使い方が無い
- テーマの違いを変数でなく部品の CSS の分岐で書いている。変数で表せない飾りは `components.css` 末尾の「テーマの飾り」にまとめ、飾りを増やすなら `docs/design.md` の「飾りの決まり」も直す
- 中世風と他とで文字が変わる飾りに、`.orn-medieval` と `.orn-plain` の片方しか無い
- `data-theme` の値が DB の列挙（`simple`、`simple_light`、`simple_dark`、`medieval`、`modern`）と違う
- 本番の Svelte のコンポーネントが、対応する `design/kit.js` の関数と違う HTML の構造やクラスを出している

## Svelte の書き方

- 開発時だけ出る Svelte と SvelteKit の警告が出る書き方をしている。`$state` でない入れ物への `bind:this`（`binding_property_non_reactive`）、SvelteKit 3 で置き換わったリンクの属性 `data-sveltekit-keepfocus` と `data-sveltekit-noscroll`（`link_option_replaced`）など（e2e が確かめる。CI の `e2e-dev` が開発モードの build で流し、e2e が開く画面と操作だけ）。コンパイル時の警告は `pnpm check`（`svelte-check --fail-on-warnings`）が落とす

## 色の役割

- 操作の色（`--color-accent`）、完了の色（`--color-done`）、印の色（`--color-stamp`）、経験値の色（`--color-xp`）を、決まった用途の外で使っている
- 状態（期限切れ、重量オーバー、未記入、取り込み元で完了など）を色だけで示し、アイコンか文字が無い
- 選択中を色だけで示している（`aria-pressed`、`aria-selected`、印か文字が要る）
- 現代風で、要所（レベル、積載量、貼り紙、ダイアログ、クリアの演出）以外を光らせている

## 言葉

- 画面の文言を直書きし、言葉の辞書を通していない
- 辞書にゲームの言葉かスクラムの言葉の片方しか無い
- 言葉の長さの違いで崩れる組み方（固定の幅、`white-space: nowrap` で切る、1行前提の高さ）
- ボタンの文言が押した先を表していない（「次へ」「OK」だけ）

## 状態

- 読み込み中、0件、エラー、操作できないときの表示が無い。操作できないときに理由と次にできることが無い
- 空の一覧に、何が出る場所かと次にやることが無い（`docs/design.md` の「見本を作って補ったこと」）
- 操作の結果が画面のどこにも出ない
- 取り込み元の属性（タイトル、状態、期限）が編集できそうに見える。出典（キーと取り込み元）が無い
- 人を並べたり比べたりする表示（順位、メンバー間の経験値の比較）を足している。経験値の数値を本人以外に見せている

## 読む要素と押す要素

- 集計や状態ラベルに、押せる要素と同じ枠、チップ、ホバーの表現を付けている
- 状態ラベルと操作ボタンが、形と余白で見分けられない
- 押せる要素が `<div>` や `<span>` で、キーボードで操作できない（`<button>` か `<a>` を使う）
- 同じ条件を操作するフィルターが複数の場所にある
- 集計が全件の値か絞り込み後の値か書いていない。表示しているデータと別に数えていて、表示とずれうる
- 役割の無い影、角丸、写真、アイコンを足している

## アクセシビリティ

- アイコンだけのボタンに `aria-label` が無い（e2e が確かめる。主な画面だけ）。飾りのアイコンに `aria-hidden="true"` が無い
- 入力欄に紐づいた `<label>` が無い（e2e が確かめる。主な画面だけ）。エラーの文言が入力欄に紐づいていない（`aria-describedby`）
- ダイアログを開いたときにフォーカスが移らない、閉じたときに元へ戻らない、`Esc` で閉じない（e2e が確かめる。主な画面だけ）
- `:focus-visible` の見た目を消している
- 文字と背景のコントラストが足りない（e2e が確かめる。主な画面だけ）。本文 4.5:1、大きい文字 3:1。4つのテーマそれぞれで見る。ただし、現代風で地のグラデーションの上に直に置く文字（見出し、上の帯の名前など）は、axe が判定を保留して通すので、主な画面でも目で見る（保留の数は e2e の annotation に出るが、増えても落ちない）
- UI の部品（枠、アイコン、フォーカスの輪）と背景のコントラストが 3:1 に足りない。axe は見ないので、4つのテーマそれぞれで目で見る

## 動き

- 演出が短く1回で終わらない。繰り返す
- `prefers-reduced-motion: reduce` のときに止まらない

## 崩れ

- スマホの幅（320px、390px）で横にはみ出す。長い日本語、キー、URL が折り返さない（e2e が確かめる。主な画面の 390px だけ）
- PC の幅（1024px、1280px）で、列が詰まって文字が重なる、または間延びして読む位置が遠くなる
- 薄すぎる文字（`--color-faint` を本文や読ませたい値に使う）
- 長い日本語が単語の途中や助詞の前で不自然に折り返す組み方（狭い固定幅のラベル、ボタンの文言）
- 長い項目名を省略したのに、全文を見る手段が無い
- 数値と単位、金額と通貨記号が別の行に分かれうる
- スマホで押せる範囲が 44px 四方より小さい（e2e が確かめる。主な画面の 390px だけ。中心から上下左右と斜めに 21px の点で見るので、43px 前後の箱は通り、箱の角までは見ない）

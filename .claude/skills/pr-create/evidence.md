# エビデンス（UI が変わる PR）

画面の見た目か挙動が変わる PR では、本文の `## エビデンス` 節に、変えた画面の変更前と変更後の画像を並べる。
PR テンプレートにこの節が無ければ `## 変更点` の直後に足す。

画像はセッションが撮らない。CI の `evidence` のジョブが e2e のスクリーンショットを `main` の画像と比べ、R2 に上げて PR にコメント（見出しは「e2e の画面の差分」）を付けるので、その画像の URL を本文に埋め込む（`docs/development.md` の「e2e の画像のコメント」）。手元のセッションもクラウドのセッションも同じ手順で行う。

- 作成の時点（`pr-create`）: 1 と 2 で、画面ごとの説明と画像の置き場の印だけを書く
- CI の完了の後（`pr-feedback` の手順 5）: 3 で、印に画像を埋め込む。push で画像が変わったときも同じ手順で差し替える

画像が付くのは e2e が開く画面だけで、枠や注記は付かず、動きは写らない。どこを見ればよいか、どの操作のときの動きかは説明の文章で伝える。

## 1. UI が変わる画面を決める

Step 2 で読んだ差分から判定する。テンプレート、コンポーネント、CSS、画面に出る文言、画像の変更は UI 変更とみなす。
API やバッチだけの変更でも、画面の表示結果が変わるなら UI 変更に含める。
判定に迷ったら UI 変更として扱う。

UI 変更と判定した画面ごとに、変えた画面と状態を開く e2e のテストを決め、その画面の名前（キー）を取る。

- キーは `<テストのディレクトリの名前>/evidence-<n>.png`。CI のコメントの JSON の `key` と同じ形
- 取り方: ワークツリーで `E2E_EVIDENCE=1 pnpm e2e <ファイル>` を走らせ、`test-results/<ディレクトリ>/evidence-<n>.png` を見る（再試行の `-retry<n>` はキーに含めない）。`n` はテストの終わりに開いている画面ごとに 1 から増える
- 撮れた画像を Read し、変えた所が写っているかを確かめる。写っていなければ、テストの終わりの画面が変えた状態になるようにテストを足すか直す
- 変えた画面と状態を開くテストが無ければ、`done-check` の手順 5 に戻ってテストを足す（PR を作る前に済ませる）

## 2. 作成の時点の節を書く

```markdown
## エビデンス

<!-- evidence: pending -->

### <画面名>

<何が変わったか。どこを見ればよいか。動きが変わる画面は、どの操作をしたときの動きか>

<!-- evidence-images: <キー> -->
画像は CI の完了の後に入る。
<!-- /evidence-images -->

全画面の差分は <!-- evidence-comment -->CI の `evidence` のコメント（e2e の画面の差分）<!-- /evidence-comment --> にある。
```

- 画面ごとに `###` と説明と印の組を並べる。説明は印の外に書く（3 は印の中だけを書き換える）
- 新しく作った画面は、説明に「新しい画面なので変更前は無い」と書く
- 1つのテストが2つの画面を撮るなら、キーごとに印を分ける

## 3. 画像を埋め込む

`pr-feedback` の手順 5 で、check-runs がすべて `completed` になった後に行う。push のたびに毎回行う。本文の `<!-- evidence: <SHA> -->` が今の head と同じでも飛ばさない（同じコミットで CI を走らせ直すと画像が変わることがあり、本文に印を足しても SHA は変わらないため）。

1. コメント、本文、PR の head の SHA を取る。本文は書き換える直前に取り直す（人や他のセッションの編集を消さないため）

   ```bash
   gh api "repos/{owner}/{repo}/issues/<n>/comments" --paginate --slurp > "<スクラッチパッドの絶対パス>/evidence-comments.json"
   gh api "repos/{owner}/{repo}/pulls/<n>" --jq .body > "<スクラッチパッドの絶対パス>/pr-body.md"
   gh api "repos/{owner}/{repo}/pulls/<n>" --jq .head.sha
   ```

2. [embed-evidence.py](embed-evidence.py) を走らせる。`evidence` のチェックが成功していなければ、最後に付かなかった理由を渡す
   - チェックが失敗した: ジョブの注記とログから理由を取る（例 `evidence のジョブが失敗した`）
   - チェックが無いか `skipped`: `evidence` が動かない PR（文書だけ、fork、Bot の PR）。例 `evidence が動かない PR（文書だけの差分）`
   - 成功したが上げる先の用意が無い（ジョブの注記「e2e の画像を上げない」）: コメントが付かないので、注記の文を理由に渡す

   ```bash
   python3 -I <このディレクトリの絶対パス>/embed-evidence.py <本文> <コメント> <出力> <head の SHA> [<付かなかった理由>]
   ```

   スクリプトは、コメントの目印 `<!-- e2e-evidence -->` の次の行の JSON（`<!-- e2e-evidence-data {...} -->`。`scripts/evidence.ts` の `evidenceData`）を読み、`## エビデンス` 節の中だけを書き換える。印ごとに画像の表を入れ、`<!-- evidence: ... -->` を head の SHA にし、コメントへのリンクを入れる。次のときは画像を入れず、印の中に「CI の画像は付かなかった: <理由>」と書く。前の push で画像を入れた印は消さずに残す（節の `<!-- evidence: <SHA> -->` がその画像の head を示す）
   - コメントが無い、またはコメントに JSON の行が無い
   - コメントの `headSha` が今の head と違う（前の push のコメントが残っている）
   - CI が比べられなかった（`comparedSha` が `null`）
   - 付かなかった理由を渡した

3. 出力の最後の行が「本文を書き換える」のときだけ、`gh api -X PATCH repos/{owner}/{repo}/pulls/<n> -F body=@<出力>` で書き換える。書き換えると `label` のワークフロー（`edited` で動く）が走るので、check-runs を取り直し、`label` が `completed` になるまで待つ
4. スクリプトが出した次のものを、`pr-feedback` の説明資料の「確かめたこと」に書く
   - コメントに出たのに印の無い画面: PR が変えたと判定していない画面。本文には載せない。揺れか意図しない変更のどちらかなので、画像を見て判断を添える
   - 印があるのにコメントに無い画面: 20 画面の上限を超えたか、e2e がその状態を写していないか、`main` と同じ画像になった。印の中は「出ていない」と書いた文章になる
   - 埋め込めなかった理由

`gh` が使えないセッションは、[github-mcp.md](github-mcp.md) のとおり MCP ツールで代える。コメントは `issue_read` の `get_comments`、本文と head の SHA は `pull_request_read` の `get` で読み、スクリプトの形（コメントはページの配列の配列、本文はファイル）に書き出してから走らせる。書き換えは `update_pull_request` の `body` で行う。

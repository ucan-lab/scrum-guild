# ui-polish

画面を、宣伝ページではなく毎日使う道具として仕上げる。
案件に既存のデザインルールや共通部品があれば、そちらを優先する。この基準は無いところを埋める。

## 手順

1. 「使う人、画面の目的、主な操作」を短く示す。推測なら仮定と書く。
2. 直す画面なら、直す箇所を優先度の高い3つまでに絞り、要素名と理由を添える。問題のない箇所はそのまま残す。
3. 下の基準に沿って作るか直す。
4. 「崩れの確認」を全項目通す。表示して確かめられる環境なら実際に表示して見る。
5. 「どこを、どう変えた、使う人にとっての理由」で変更を最大3つ報告する。仮定、不足している情報、確かめられなかった操作は別に書く。説明や設計メモはチャットに書き、画面には入れない。

追加の修正を頼まれたら、その観点だけを変える。整っている箇所は前の状態を保つ。

## 残すもの

- 既存の内容、数値、機能、操作の流れ、ブランドカラー、ロゴを保つ。見た目は情報を残したまま整える
- 料金、条件、実績、口コミなどの事実は与えられたものだけを使う。足りなければ画面には足さず、不足として報告する
- 検索、絞り込み、詳細表示など既存の動作を保つ

## 文字と余白

- 最初に読みたい情報と主な操作を決め、文字の大きさ、太さ、位置で強弱をつける。強調するのはその少数だけ
- 操作や一覧が中心の画面は、見出しを控えめにし、余白を情報の区切りに使う
- サイズの目安。端末と読む量で調整し、読みやすさが落ちる手前で止める

| 役割 | サイズ |
| --- | --- |
| 画面見出し | 20〜24px |
| 本文、項目名 | 14〜16px |
| 補足 | 12〜14px |
| スマホの主な操作の押せる範囲 | 44px 四方以上 |

- 文字サイズと押せる範囲は別々に決める
- 同じ役割の文字、左右の端、価格や数値の位置を揃える。関係する情報は近づけ、別のまとまりとの間に余白を置く
- 比べる内容に合わせてリスト、表、カードを選ぶ
- 日本語と数字はサンセリフ体で揃え、数字は斜体や装飾の無い字形にする。アイコンは線の太さが揃った1つのセットから選ぶ

## 読む要素と押す要素

- 件数や合計などの集計は枠のない普通の文字にする。チップ、枠、ホバー表現は押せる要素だけに付ける
- 状態ラベルは操作ボタンと形と余白で区別する
- 同じ条件を操作するフィルターは1か所にまとめる。集計は全件の値か絞り込み後の値かを明記し、表示データから計算する
- 選択状態は色に加えて文字か印でも示す
- 写真、影、角丸、アイコンは役割のあるものだけ残す

## 操作と状態

- ボタンの文言は押した先が分かる言葉にする。「次へ」ではなく「空いている日時を見る」
- 選択中、未入力、0件、エラーの状態を作る。操作できないときは理由と次にできることを出す
- 操作の結果は画面内に表示する
- 画面に置くのは実際に動く機能だけにする

## 崩れの確認

- 確認する幅はスマホが 320px と 390px、PC が 1280px と 1024px。既存の画面なら元の幅とそれより狭い幅
- 文字の重なり、横はみ出し、薄すぎる文字、長い日本語の不自然な折り返しが無い
- 長い項目名は折り返して全文が読める。省略するならクリックかタップで全文が出る
- 金額と通貨記号、件数と単位が一続きで表示される。収まらなければまとまりごとに行を分ける
- 報告に「確認済み」と書くのは、実際に表示か操作をしたものだけ

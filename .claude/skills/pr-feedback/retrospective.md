# ラウンド後の振り返り

このラウンドで分かったことのうち、次の PR でも効くものを拾い、pr-feedback に取り入れるかをユーザーに提案する。
スキルを書き換えるのはユーザーが選んだものだけ。

## 1. 材料を集める

見る材料は次の 3 つで、全部に目を通すこと。

| 材料 | 取り方 |
| --- | --- |
| リプライの提案と実際の投稿の差 | スクラッチパッドの `pr-feedback-<number>-drafts.json` と、投稿済みのコメント本文を比べる。投稿済みの本文は `gh api "repos/{owner}/{repo}/pulls/{number}/comments" --paginate` の、自分が書いたもので `in_reply_to_id` が下書きのコメント ID と一致するもの |
| セッション中のユーザーの訂正 | 対応方針、直し方、リプライの文面、手順について、ユーザーが Claude の案を変えさせた指示 |
| つまずき | 失敗したコマンド、やり直した手順、スキルに書かれていない判断を迫られた場面 |

bot へのリプライはユーザーが見ないまま投稿されるので、差の材料は人へのリプライだけになる。

完了条件: 下書きの全件が「そのまま」「書き換え」「削除（投稿されなかった）」のどれかに分類され、人が足したリプライは「追加」として拾われている。

## 2. 取り入れるかを判断する

学びごとに次を順に確かめ、全部に当てはまるものだけを提案の候補にする。

1. 次の PR でも同じことが起きる。その PR の事情だけで起きた直し（指摘の読み違いを正した、など）は外す
2. `SKILL.md` と `retrospective.md` に同じ内容が無い。あれば、効かなかった理由（文言が曖昧、書いてある場所が手順から遠い、など）を添えて書き換え案にする
3. リポジトリ固有の慣習ではない。固有のものはそのリポジトリの `AGENTS.md` か `CLAUDE.md` への追記案にする
4. レビューで見逃した問題ではない。見逃しは SKILL.md の手順 8 のチェックリストへの追記に回す
5. 環境やツールの落とし穴（sandbox で失敗したコマンド、`gh` の TLS エラーなど）ではない。落とし穴の行き先はグローバルの `CLAUDE.md` の落とし穴の節で、既に書いてあれば候補にしない

完了条件: 材料の全件に「候補」か、外した理由の 1 行が付いていること。

## 3. 提案する

候補は次も起きそうなものから 2 件までに絞り、残りは件数と一言だけ添える（理由: 並べると選別の手間がかかる）。
候補ごとに、学びの根拠（提案した文面と投稿された文面、または訂正の指示）と、足す場所と文言を並べる。
候補を `AskUserQuestion` の `multiSelect` で出し、取り入れるものを選んでもらう。候補が無ければ「学びなし」と、外した材料の件数と理由を報告して終える。

## 4. 取り入れる

選ばれたものだけを、このリポジトリの `.claude/skills/pr-feedback/` に書き込む。
このスキルの原本は `ucan-lab/claude-skills` にある。原本にも同じ変更が要るかをユーザーに伝える。
コミットはユーザーの指示を待つ。

# seed

手元の D1 と e2e に入れる架空のデータ。名前は `design/sample-data.js` から取った。

```bash
pnpm db:seed
```

流すのは `scripts/db-seed.ts` で、手元の D1 に全マイグレーションを当て、マイグレーションの記録を除く全部の表の行を消してから入れ直す。手で足した行も消えるので、何度流しても同じ状態に戻せる。

| ファイル | 中身 |
| --- | --- |
| `data.sql` | 固定の行。組織3つ（あおば開発、ひばり工房と、末尾の e2e 専用のくもラボ）、ユーザー（あおば開発には、e2e の組織の管理のユーザーの節（`e2e/users.test.ts`）だけが指名、解除、無効化、有効化する、所属もアカウントも無いソラとユイを含む。ソラは受託開発チームへの承諾待ちの招待と同じログインを持つので、管理者にしても組織の人数は変わらない）、組織の休日（あおば開発に3日、ひばり工房に1日）、ワークスペース（受託開発チームはゲームの言葉、社内ツールはスクラムの言葉、ひばり工房のデザイン相談室はゲームの言葉）、列、決まった欄、所属、承諾待ちの招待（ワークスペースごとに1件。社内ツールの分は e2e の取り消しが消してテストの後で戻し、デザイン相談室の分は招待だけが届いた人（ヒナタ）宛てで、e2e の承諾が使ってテストの後で戻す）、区分とリポジトリ（受託開発チームに2つずつ、社内ツールに1つずつ。エピック、親のないタスク、ストーリーの下のタスクに少し振る）、エピック（受託開発チームに1件。その下に、配下のタスクがすべて完了したストーリー1件。討伐隊はミナトとハルカの2人。所属の無いユーザーは、運用者の指名し直しが物理削除するので入れない）、親のないストーリー、タスク（親のないタスクと、ストーリーの下の未完了のものと完了したもの。期日が過ぎたものと今週のものを含む）、先のスプリント（受託開発チームに2つ。名前のないものと名前のあるもの。それぞれにストーリーの下の未完了のタスクを1件ずつ入れ、入った行（`sprint_entries`）を置く。社内ツールとデザイン相談室には置かない）、終了したスプリント（受託開発チームに1つ。先のスプリントより前の期間（2026-10-05〜2026-10-18）で、ゴールを書き、達成した。完了したタスク2件（ストーリーの下の完了したもの）は終えたスプリントの完了の列に残り、完了の記録（`completions`。`sprint_id` がこのスプリント。1件は経験値の明細の `completion_id` と同じ id）と `completed` で閉じた行を置く。終わらなかった2件のタスク（先のスプリントに入れた2件）は、このスプリントでの行を `carried_over` で閉じて先のスプリントへ持ち越し、先のスプリントの開いた行の `added_at` は持ち越した日時にそろえる。#244 のベロシティが使う）、進行中のスプリント（デザイン相談室に1つ。ゴールを書き、各列に1〜2件と完了の列に1件のタスクを置いて入った行も置く。手元でスプリントの画面を見る行で、`pnpm dev:open otherOrg /hibari/w/019a0000-0000-7000-8000-000000000404/sprint` で開く）、変更の履歴（組織の作成と最初の管理者の指名、受託開発チームの作成と所属、あおば開発の一時的な停止と再開）、経験値の明細（あおば開発のミナトに完了したタスクの起票と完了の2行。ひばり工房のミナトに、自分の設定の画面の「続きを読む」を確かめる、完了と打ち消しをくり返した52行）。日時は 2026-10-20 前後に固定。末尾に、e2e の組織の言葉づかいと既定のテーマ（`e2e/organization-look.test.ts`）だけが使う3つ目の組織（くもラボ。その e2e が組織の値を書き換えるので、ほかのファイルが確かめる組織と分けた）と、その中の3人（管理者、テーマを選んでいない一般、テーマを選んだ一般。どれもほかの組織に入らない専用のアカウント）、一般の2人が入るためのワークスペース1つ。その後に、メールアドレスとパスワードでログインする2人（下の「パスワード」）の資格情報（`password_credentials`）と、2人だけが入る専用の組織2つ（ゆず書房とみなも舎。ワークスペースは持たない）とその管理者の行 |
| `sessions.ts` | ログインに使うセッションのトークン10個と、運用者のログインの ID |
| `passwords.ts` | メールアドレスとパスワードでログインする2人のメールアドレスとパスワード |

## セッション

トークンの値の置き場所は `sessions.ts` だけ。`sessions.token_hash` にはその SHA-256 の16進を、`last_used_at` には流した時刻を、`expires_at` にはその30日後を入れ、切れたら流し直す。人が画面を開くときは `pnpm dev:open [--preview] [who] [path]` が、このトークンの Cookie を置いたブラウザで開く（`docs/development.md` の「開発とテストでのログイン」）。手で Cookie を置くときの名前は、画面を開く URL が http の localhost（`pnpm dev`、`pnpm preview`）なら `sg_session`、https なら `__Host-sg_session`（`src/shared/session-cookie.ts` の `sessionCookieName()`）。e2e も同じ関数で名前を決める。

| キー | 人 |
| --- | --- |
| `admin` | あおば開発の管理者（ミナト）。ひばり工房では一般のユーザー |
| `member` | あおば開発の一般のユーザー（ハルカ） |
| `otherOrg` | ひばり工房だけに入れる管理者（リン） |
| `invitee` | どの組織にも `users` の行を持たず、ひばり工房のデザイン相談室への承諾待ちの招待だけが届いた人（ヒナタ）。e2e が承諾すると、デザイン相談室の一般のメンバーになる（その e2e がテストの後で手元の D1 に直に書いて戻す。`e2e/local-d1.ts`。`pnpm db:seed` でも戻る） |
| `operator` | どの組織にも属さない運用者。ログインの ID は `.dev.vars.example` の `OPERATOR_LOGIN_IDS` と同じ `github:9000000000000001`（実在の人に当たらないよう、GitHub がまだ振っていない桁にした） |
| `adminLogout` | `admin` と同じアカウント（ミナト）の2本目。e2e のログアウトが消す行 |
| `operatorLogout` | `operator` と同じアカウントの2本目。e2e のログアウトが消す行 |
| `lookAdmin` | くもラボの管理者（カイ）。e2e の組織の言葉づかいと既定のテーマ（`e2e/organization-look.test.ts`）が使う |
| `lookMember` | くもラボの一般のユーザーで、テーマを選んでいない（ソウタ） |
| `lookThemed` | くもラボの一般のユーザーで、自分のテーマ（シンプル（ダーク））を選んでいる（コハル） |

e2e は seed のセッションを全ファイルで共有し、ファイルを並列に走らせる。共有の `admin` や `operator` をログアウトすると、ほかのテストが 401 で落ちるので、ログアウトの e2e（`e2e/logout.test.ts`）は専用の2本だけを消す。ログアウトは今のセッションだけを消すので、同じアカウントの `admin` と `operator` は残る。消えた行は `pnpm db:seed` で戻る（`pnpm e2e` は毎回流し直す）。繰り返し（`--repeat-each`）の間は seed を流し直さないので、ログアウトの e2e は消す前に専用の行を手元の D1 へ入れ直す（`e2e/local-d1.ts`）。

## パスワード

メールアドレスとパスワードの値の置き場所は `passwords.ts` だけ。`data.sql` の `password_credentials.password_hash` には、そのパスワードを `hashPassword`（`src/server/auth/password-hash.ts`、反復回数 100,000）で作ったハッシュを固定の文字列で書く。パスワードを変えたら、ハッシュも作り直して `data.sql` を直す（`scripts/seed.test.ts` が、ハッシュがパスワードと今の反復回数に合うことを確かめる）。アカウントと `account_logins` の行は入れず、ほかの手段と同じく初めてのログインで作る。手元の画面では、ログインの画面（`/login`）の欄にこのメールアドレスとパスワードを入れて入る。

| キー | 人 | メールアドレス | パスワード |
| --- | --- | --- | --- |
| `single` | ゆず書房だけに入れる管理者（ツムギ）。ログインするとゆず書房の画面へ移る | `tsumugi@example.test` | `seed-password-tsumugi` |
| `multi` | ゆず書房とみなも舎に入れる管理者（アオイ）。ログインすると組織の選択（`/`）へ移る | `aoi@example.test` | `seed-password-aoi` |

ログインの e2e（`e2e/password-login.test.ts`）だけが使う。パスワードのログインのレート制限（同じメールアドレスに10分に10回）を繰り返し（`--repeat-each`）で使い切らないよう、その e2e は場面ごとに手元の D1 のパスワードの枠の行（`rate_limits` の `password` で始まるキー）を消してから試す（`e2e/local-d1.ts`）。

## 本番に入れない

トークンとパスワードは、リポジトリを読める人なら誰でも知っている値。本番の D1 に入れば、その人たちが管理者や運用者としてログインできてしまう。

- `scripts/db-seed.ts` が付けるのは `--local` だけで、`--remote` はフックの `guard-bash.mjs` も止める
- `seed/` の SQL は `wrangler d1 execute --remote` に渡さない
